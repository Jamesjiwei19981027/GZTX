# 03 - 数据库设计文档

> 本文档描述工作待办提醒系统的数据模型、表结构设计和关系定义。

---

## 一、设计原则

1. **第三范式为主**：减少数据冗余，保证数据一致性
2. **适当反规范化**：在查询性能和数据一致性之间权衡
3. **软删除优先**：保留历史数据，支持恢复
4. **时间戳必备**：每条记录包含 created_at 和 updated_at
5. **索引优化**：高频查询字段建立索引

## 三、表结构详细设计

### 3.1 users（用户表）

存储系统用户信息，支持账号密码登录和微信登录。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | INTEGER | PK, AUTO_INCREMENT | - | 主键 |
| username | VARCHAR(50) | UNIQUE, NOT NULL | - | 用户名 |
| email | VARCHAR(100) | UNIQUE | NULL | 邮箱 |
| password_hash | VARCHAR(255) | - | NULL | 密码哈希（bcrypt）|
| nickname | VARCHAR(50) | - | NULL | 昵称 |
| avatar_url | VARCHAR(255) | - | NULL | 头像URL |
| wx_openid | VARCHAR(100) | UNIQUE | NULL | 微信OpenID |
| wx_unionid | VARCHAR(100) | UNIQUE | NULL | 微信UnionID |
| is_active | BOOLEAN | NOT NULL | TRUE | 是否激活 |
| notify_pref | JSON | - | '{}' | 通知偏好设置 |
| created_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

**索引**：
- `idx_username` ON username
- `idx_email` ON email
- `idx_wx_openid` ON wx_openid

**说明**：
- `password_hash` 和 `wx_openid` 至少有一个不为空
- `notify_pref` JSON 结构示例：
  ```json
  {
    "email_enabled": true,
    "web_push_enabled": true,
    "wx_subscribe_enabled": true,
    "daily_digest_time": "08:00",
    "default_remind_before": 15
  }
  ```

---

### 3.2 categories（分类表）

用户自定义的任务分类，如工作、个人、学习等。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | INTEGER | PK, AUTO_INCREMENT | - | 主键 |
| user_id | INTEGER | FK, NOT NULL | - | 所属用户 |
| name | VARCHAR(50) | NOT NULL | - | 分类名称 |
| color | VARCHAR(7) | NOT NULL | '#409EFF' | 颜色（HEX格式）|
| icon | VARCHAR(50) | - | NULL | 图标名称 |
| sort_order | INTEGER | NOT NULL | 0 | 排序顺序 |
| is_default | BOOLEAN | NOT NULL | FALSE | 是否默认分类 |
| created_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**索引**：
- `idx_user_id` ON user_id
- `idx_user_sort` ON (user_id, sort_order)

**说明**：
- 每个用户至少有一个默认分类
- 删除分类时，该分类下的任务自动移到默认分类

---

### 3.3 tags（标签表）

用户自定义标签，用于跨分类标记任务。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | INTEGER | PK, AUTO_INCREMENT | - | 主键 |
| user_id | INTEGER | FK, NOT NULL | - | 所属用户 |
| name | VARCHAR(30) | NOT NULL | - | 标签名称 |
| color | VARCHAR(7) | NOT NULL | '#67C23A' | 颜色 |
| created_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**索引**：
- `idx_user_id` ON user_id
- `idx_user_name` ON (user_id, name) UNIQUE

---

### 3.4 tasks（任务表）

核心表，存储所有待办任务。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | INTEGER | PK, AUTO_INCREMENT | - | 主键 |
| user_id | INTEGER | FK, NOT NULL | - | 所属用户 |
| category_id | INTEGER | FK, NOT NULL | - | 所属分类 |
| title | VARCHAR(200) | NOT NULL | - | 任务标题 |
| description | TEXT | - | NULL | 任务描述 |
| priority | INTEGER | NOT NULL | 1 | 优先级：0-低, 1-中, 2-高 |
| status | INTEGER | NOT NULL | 0 | 状态：0-待办, 1-进行中, 2-已完成 |
| due_date | DATETIME | - | NULL | 截止日期 |
| completed_at | DATETIME | - | NULL | 完成时间 |
| is_recurring | BOOLEAN | NOT NULL | FALSE | 是否重复任务 |
| recurrence_rule | JSON | - | NULL | 重复规则 |
| parent_task_id | INTEGER | FK, NULL | NULL | 父任务ID（子任务）|
| sort_order | INTEGER | NOT NULL | 0 | 排序顺序 |
| is_deleted | BOOLEAN | NOT NULL | FALSE | 是否删除 |
| deleted_at | DATETIME | - | NULL | 删除时间 |
| created_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

**索引**：
- `idx_user_status` ON (user_id, status)
- `idx_user_due_date` ON (user_id, due_date)
- `idx_user_deleted` ON (user_id, is_deleted)
- `idx_parent_task` ON parent_task_id
- `idx_recurring` ON is_recurring

**说明**：
- `recurrence_rule` JSON 结构示例：
  ```json
  {
    "frequency": "weekly",
    "interval": 1,
    "days_of_week": [1, 3, 5],
    "end_type": "never",
    "end_date": null,
    "occurrences": null
  }
  ```
  - `frequency`: daily/weekly/monthly/yearly
  - `interval`: 每隔N个周期
  - `days_of_week`: 周几（0=周日）
  - `end_type`: never/date/occurrences

- `priority` 枚举：
  - 0: 低（Low）
  - 1: 中（Medium）
  - 2: 高（High）

- `status` 枚举：
  - 0: 待办（Todo）
  - 1: 进行中（In Progress）
  - 2: 已完成（Done）

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| task_id | INTEGER | PK, FK | - | 任务ID |
| tag_id | INTEGER | PK, FK | - | 标签ID |

**索引**：
- `idx_task_id` ON task_id
- `idx_tag_id` ON tag_id

### 3.6 reminders（提醒表）

存储任务的提醒设置和发送记录。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | INTEGER | PK, AUTO_INCREMENT | - | 主键 |
| task_id | INTEGER | FK, NOT NULL | - | 关联任务 |
| user_id | INTEGER | FK, NOT NULL | - | 所属用户 |
| remind_at | DATETIME | NOT NULL | - | 提醒时间 |
| remind_type | INTEGER | NOT NULL | 0 | 提醒类型 |
| is_sent | BOOLEAN | NOT NULL | FALSE | 是否已发送 |
| sent_at | DATETIME | - | NULL | 发送时间 |
| created_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**索引**：
- `idx_remind_at` ON remind_at
- `idx_task_id` ON task_id
- `idx_user_sent` ON (user_id, is_sent)

**说明**：
- `remind_type` 枚举：
  - 0: 截止前提醒
  - 1: 截止时提醒
  - 2: 逾期提醒
  - 3: 自定义时间提醒

### 3.7 recurring_instances（重复任务实例表）

记录重复任务生成的具体实例，用于单独修改某次重复任务。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | INTEGER | PK, AUTO_INCREMENT | - | 主键 |
| task_id | INTEGER | FK, NOT NULL | - | 原始重复任务 |
| instance_date | DATE | NOT NULL | - | 实例日期 |
| title | VARCHAR(200) | - | NULL | 覆盖标题 |
| description | TEXT | - | NULL | 覆盖描述 |
| status | INTEGER | NOT NULL | 0 | 实例状态 |
| completed_at | DATETIME | - | NULL | 完成时间 |
| is_modified | BOOLEAN | NOT NULL | FALSE | 是否被单独修改 |
| created_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**索引**：
- `idx_task_date` ON (task_id, instance_date) UNIQUE

## 四、SQLAlchemy 模型定义（参考）

```python
# backend/app/models/user.py
from sqlalchemy import Column, Integer, String, Boolean, DateTime, JSON
from sqlalchemy.sql import func
from app.db.base import Base

class User(Base):
    __tablename__ = "users"
    
    id = Column(Integer, primary_key=True, index=True)
    username = Column(String(50), unique=True, index=True, nullable=False)
    email = Column(String(100), unique=True, index=True, nullable=True)
    password_hash = Column(String(255), nullable=True)
    nickname = Column(String(50), nullable=True)
    avatar_url = Column(String(255), nullable=True)
    wx_openid = Column(String(100), unique=True, index=True, nullable=True)
    wx_unionid = Column(String(100), unique=True, nullable=True)
    is_active = Column(Boolean, default=True, nullable=False)
    notify_pref = Column(JSON, default={})
    created_at = Column(DateTime(timezone=True), server_default=func.now())
    updated_at = Column(DateTime(timezone=True), onupdate=func.now())
```

```python
# backend/app/models/task.py
from sqlalchemy import Column, Integer, String, Text, Boolean, DateTime, ForeignKey, JSON
from sqlalchemy.orm import relationship
from sqlalchemy.sql import func
from app.db.base import Base

class Task(Base):
    __tablename__ = "tasks"
    
    id = Column(Integer, primary_key=True, index=True)
    user_id = Column(Integer, ForeignKey("users.id"), nullable=False, index=True)
    category_id = Column(Integer, ForeignKey("categories.id"), nullable=False)
    title = Column(String(200), nullable=False)
    description = Column(Text, nullable=True)
    priority = Column(Integer, default=1, nullable=False)  # 0=low, 1=medium, 2=high
    status = Column(Integer, default=0, nullable=False)    # 0=todo, 1=in_progress, 2=done
    due_date = Column(DateTime(timezone=True), nullable=True, index=True)
    completed_at = Column(DateTime(timezone=True), nullable=True)
    is_recurring = Column(Boolean, default=False, nullable=False)
    recurrence_rule = Column(JSON, nullable=True)
    parent_task_id = Column(Integer, ForeignKey("tasks.id"), nullable=True)
    sort_order = Column(Integer, default=0, nullable=False)
    is_deleted = Column(Boolean, default=False, nullable=False, index=True)
    deleted_at = Column(DateTime(timezone=True), nullable=True)
    created_at = Column(DateTime(timezone=True), server_default=func.now())
    updated_at = Column(DateTime(timezone=True), onupdate=func.now())
    
    # Relationships
    user = relationship("User", back_populates="tasks")
    category = relationship("Category", back_populates="tasks")
    tags = relationship("Tag", secondary="task_tags", back_populates="tasks")
    reminders = relationship("Reminder", back_populates="task", cascade="all, delete-orphan")
    sub_tasks = relationship("Task", backref="parent", remote_side=[id])
```

## 五、数据库迁移策略

### 5.1 使用 Alembic 管理迁移

```bash
# 初始化 Alembic
alembic init alembic

# 创建迁移脚本（自动检测模型变化）
alembic revision --autogenerate -m "create initial tables"

# 执行迁移
alembic upgrade head

# 回滚一次迁移
alembic downgrade -1
```

### 5.2 迁移脚本命名规范

- `create_xxx_table`：创建表
- `add_xxx_column`：添加字段
- `modify_xxx_xxx`：修改字段
- `drop_xxx_table`：删除表

## 七、性能优化策略

### 7.1 索引策略

| 查询场景 | 索引 |
|---------|------|
| 用户任务列表 | (user_id, is_deleted, status) |
| 今日待办 | (user_id, is_deleted, due_date) |
| 提醒查询 | (remind_at, is_sent) |
| 分类筛选 | (user_id, category_id, is_deleted) |

### 7.2 分页策略

- 任务列表默认每页 20 条
- 最大每页 100 条
- 使用游标分页（cursor-based）处理大量数据

### 7.3 数据归档

- 已完成超过 1 年的任务自动归档
- 归档数据移到单独表 `task_archives`
- 提供"查看归档"功能

## 八、备份策略

```bash
# 每日自动备份
cp worktodo.db backups/worktodo_$(date +%Y%m%d).db

find backups/ -name "worktodo_*.db" -mtime +30 -delete
```

```bash
# 使用 pg_dump 每日备份

```
