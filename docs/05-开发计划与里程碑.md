# 05 - 开发计划与里程碑

> 本文档详细描述工作待办提醒系统的开发阶段划分、任务分解、时间安排和验收标准。

---

## 一、开发方法论

### 1.1 采用敏捷开发

- **迭代周期**：每 2 周一个 Sprint
- **每日站会**：同步进度、识别阻塞
- **迭代评审**：演示完成功能，收集反馈
- **迭代回顾**：总结经验，持续改进

### 1.2 MVP 优先策略

第一阶段只实现核心功能，快速验证价值：
- 用户注册登录
- 任务的增删改查
- 基础提醒功能
- Web 端 + 小程序双端

扩展功能（统计、自然语言、团队协作）后续迭代。

## 七、开发规范

### 7.1 Git 工作流

采用 Git Flow 简化版：

```
main (生产分支)
  ↑
develop (开发分支)
  ↑
feature/xxx (功能分支)
  ↑
hotfix/xxx (紧急修复)
```

- 功能开发从 develop 切出 feature 分支
- 完成后合并回 develop
- 每个迭代结束，develop 合并到 main 并打 tag

### 7.2 代码提交规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

Type 类型：
- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档更新
- `style`: 代码格式（不影响功能）
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/工具相关

示例：
```
feat(task): 添加任务重复功能

- 支持按日/周/月/年重复
- 可单独修改某次实例
- 添加相关单元测试

Closes #123
```

### 7.3 代码审查清单

- [ ] 代码符合项目规范
- [ ] 有足够的单元测试
- [ ] 无明显的安全漏洞
- [ ] 性能无明显问题
- [ ] 文档已更新
