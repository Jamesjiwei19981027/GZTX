## 二、开发环境搭建

### 2.1 克隆项目

```bash
git clone <repository-url>
cd worktodo
```

### 2.2 后端环境

```bash
cd backend

# 创建虚拟环境
python -m venv venv

# Windows
venv\Scripts\activate

# macOS/Linux
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 配置环境变量
cp .env.example .env
# 编辑 .env 文件

# 运行数据库迁移
alembic upgrade head

# 启动开发服务器
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 2.3 前端环境（React 19 + Vite，真源 `frontend/`）

```bash
cd frontend

# 安装依赖（推荐可复现安装）
npm ci
# 或：npm install

# 可选：本地环境变量（生产镜像内默认 VITE_API_BASE_URL=/api/v1）
# cp .env.example .env.local

# 启动开发服务器（Vite，默认 http://localhost:5173）
npm run dev

# 生产构建 / 类型检查 / 单测 / E2E
npm run build
npm run typecheck
npm test
npm run test:e2e
```

> **归档**：历史 Vue3 代码在 `frontend-vue-archive/`，仅用于对照与回滚，**不要**当作现役前端开发。

### 2.4 Docker 一键启动

```bash
# 开发环境
docker-compose -f docker-compose.yml up -d

# 查看日志
docker-compose logs -f backend
docker-compose logs -f frontend
```

## 三、生产环境部署

### 3.1 服务器准备

#### 购买云服务器（以腾讯云为例）

1. 登录腾讯云控制台
2. 购买轻量应用服务器（2核4G，Ubuntu 22.04）
3. 配置安全组，开放端口：
   - 22 (SSH)
   - 80 (HTTP)
   - 443 (HTTPS)

#### 域名和 SSL

1. 购买域名并解析到服务器 IP
2. 申请免费 SSL 证书（Let's Encrypt）

### 3.2 服务器初始化

```bash
# 连接服务器
ssh root@your-server-ip

# 更新系统
apt update && apt upgrade -y

# 安装必要工具
apt install -y git curl wget vim nginx certbot python3-certbot-nginx

# 安装 Docker
curl -fsSL https://get.docker.com | sh
systemctl enable docker
systemctl start docker

# 安装 Docker Compose
apt install -y docker-compose-plugin
```

### 3.3 部署应用

```bash
# 创建应用目录
mkdir -p /opt/worktodo
cd /opt/worktodo

# 克隆代码
git clone <repository-url> .

# 配置生产环境变量
cp backend/.env.example backend/.env
vim backend/.env

# 关键配置项：
# DATABASE_URL=postgresql://user:pass@db:5432/worktodo
# SECRET_KEY=your-strong-secret-key
# WX_APP_ID=your-wx-app-id
# WX_APP_SECRET=your-wx-app-secret

# 启动服务
docker-compose -f docker-compose.prod.yml up -d

# 查看状态
docker-compose ps
docker-compose logs -f
```

### 3.4 Nginx 配置

```nginx
# /etc/nginx/sites-available/worktodo
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # 前端静态资源
    location / {
        root /opt/worktodo/frontend/dist;
        try_files $uri $uri/ /index.html;
        expires 30d;
    }

    # API 代理
    location /api/ {
        proxy_pass http://localhost:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Swagger 文档（三个路径都要转发，否则页面打开但加载不出接口；开关与门禁见 docs/api-swagger.md）
    location /docs {
        proxy_pass http://localhost:8000/docs;
    }
    location /redoc {
        proxy_pass http://localhost:8000/redoc;
    }
    location /openapi.json {
        proxy_pass http://localhost:8000/openapi.json;
    }

    # WebSocket（如后续需要）
    location /ws/ {
        proxy_pass http://localhost:8000/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

```bash
# 启用配置
ln -s /etc/nginx/sites-available/worktodo /etc/nginx/sites-enabled/
nginx -t
systemctl restart nginx

# 配置 SSL
certbot --nginx -d your-domain.com
```

## 四、Docker Compose 配置

### 4.1 开发环境 docker-compose.yml

```yaml
version: '3.8'

services:
  backend:
    build: ./backend
    ports:
      - "8000:8000"
    volumes:
      - ./backend:/app
      - ./data:/app/data
    environment:
      - DATABASE_URL=sqlite:///data/worktodo.db
      - SECRET_KEY=dev-secret-key
    command: uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

  frontend:
    build: ./frontend
    ports:
      - "5173:5173"
    volumes:
      - ./frontend:/app
      - /app/node_modules
    command: npm run dev -- --host 0.0.0.0

  db:
    image: postgres:15-alpine
    ports:
      - "5432:5432"
    environment:
      - POSTGRES_USER=worktodo
      - POSTGRES_PASSWORD=worktodo123
      - POSTGRES_DB=worktodo
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

### 4.2 生产环境 docker-compose.prod.yml

> 仓库真源以根目录 `docker-compose.prod.yml` 为准。前端为 **React** 多阶段镜像：`frontend/Dockerfile.prod`（`npm ci` → `npm run build` → nginx 托管 `dist`）。

```bash
# 构建并启动（需已配置 .env 中 SECRET_KEY 等）
docker compose -f docker-compose.prod.yml up -d --build

# 仅重建前端生产镜像
docker compose -f docker-compose.prod.yml build frontend
```

要点：

| 服务 | 构建 | 说明 |
|------|------|------|
| `migrate` | `backend/Dockerfile.prod` | 一次性执行 `alembic upgrade head`，失败则阻止应用启动 |
| `backend` | `backend/Dockerfile.prod` | FastAPI + 迁移成功后启动 |
| `frontend` | `frontend/Dockerfile.prod` | React 静态资源 + 容器内 nginx |
| `nginx` | 官方镜像 | 反代 `/api` → backend，`/` → frontend |
| `db` | `postgres:15-alpine` | 生产库 |

开发环境热重载前端使用 `frontend/Dockerfile`（Vite 5173），见 `docker-compose.yml`。

## 五、备份策略

### 5.1 数据库自动备份

```bash
#!/bin/bash
# /opt/worktodo/scripts/backup.sh

BACKUP_DIR="/opt/worktodo/backups"
DB_CONTAINER="worktodo-db-1"
DATE=$(date +%Y%m%d_%H%M%S)

# 创建备份
docker exec $DB_CONTAINER pg_dump -U worktodo worktodo > $BACKUP_DIR/worktodo_$DATE.sql

# 压缩备份
gzip $BACKUP_DIR/worktodo_$DATE.sql

# 删除 30 天前的备份
find $BACKUP_DIR -name "worktodo_*.sql.gz" -mtime +30 -delete

# 可选：上传到对象存储
# aws s3 cp $BACKUP_DIR/worktodo_$DATE.sql.gz s3://your-bucket/backups/
```

```bash
# 添加定时任务（每天凌晨 2 点执行）
crontab -e
0 2 * * * /opt/worktodo/scripts/backup.sh >> /var/log/worktodo-backup.log 2>&1
```

### 5.2 数据恢复

```bash
# 停止应用
docker-compose -f docker-compose.prod.yml stop backend

# 恢复数据
gunzip -c backups/worktodo_20260528_020000.sql.gz | docker exec -i worktodo-db-1 psql -U worktodo worktodo

# 重启应用
docker-compose -f docker-compose.prod.yml start backend
```

HEALTH_URL="https://your-domain.com/api/v1/health"
WEBHOOK_URL="https://your-webhook-url"

response=$(curl -s -o /dev/null -w "%{http_code}" $HEALTH_URL)

if [ "$response" != "200" ]; then

        -H "Content-Type: application/json" \
        -d '{"text": "WorkTodo 服务异常，HTTP状态码: '$response'"}'

## 七、故障处理

### 7.1 常见问题排查

| 问题 | 排查步骤 | 解决方案 |
|------|---------|---------|
| 服务无法启动 | 查看日志 `docker-compose logs` | 检查环境变量、端口占用 |
| 数据库连接失败 | 检查数据库服务状态 | 确认连接字符串、网络连通性 |
| API 返回 500 | 查看后端错误日志 | 检查代码异常、数据库状态 |
| 前端白屏 | 检查浏览器控制台 | 确认 API 地址配置、CORS 设置 |
| 小程序无法登录 | 检查微信配置 | 确认 AppID、AppSecret 正确 |
| 提醒不触发 | 检查定时任务状态 | 重启 APScheduler、检查时区 |

### 7.2 紧急回滚

#### 前端 React → 归档 Vue（生产切流后的应急）

> **说明**：当前阶段**尚未**声明生产已切 React。下列步骤供切流后或 staging 演练使用。验收门禁与 soak 记录见  
> `docs/superpowers/acceptance/2026-07-20-react-rewrite-gates.md`。

**方式 A：从归档目录构建旧前端镜像（推荐，可复现）**

```bash
# 1) 用 Vue 归档构建前端镜像（context 指向 archive）
docker build -f frontend-vue-archive/Dockerfile.prod \
  -t worktodo-frontend:vue-rollback \
  frontend-vue-archive

# 2) 记下当前 React 镜像 digest（便于再切回）
docker image inspect worktodo-frontend:latest --format '{{.Id}}' || true

# 3) 在 compose 中将 frontend 服务改为使用该镜像后 up
#    或临时：docker compose -f docker-compose.prod.yml stop frontend
#    docker run ... 用 worktodo-frontend:vue-rollback 替换同网络/标签
docker compose -f docker-compose.prod.yml up -d frontend
```

**方式 B：固定 tag / digest**

```bash
# 仓库保留 tag：vue-frontend-last（Vue 归档冻结点）
git checkout vue-frontend-last -- frontend-vue-archive   # 仅在需恢复归档树时

# 若运维已为 Vue 推送镜像 digest，直接改 compose image 字段指向该 digest 并 up
# 例：image: registry.example.com/worktodo-frontend@sha256:<vue-digest>
```

**演练检查清单（G6）**

1. Staging 切到 Vue 镜像 → 登录可用  
2. 再切回 React 镜像 → 登录可用  
3. 记录时间、镜像 digest / git SHA 到验收笔记  

**本地 Compose 演练脚本**

仓库提供 `scripts/rollback-drill.ps1`，默认使用独立项目名 `worktodo-drill` 和前端端口
`18080`。脚本会构建 Vue 归档镜像与当前 React 生产镜像，生成只存在于
`$env:TEMP` 的一次性密钥文件，启动完整 prod Compose，注册演练账号，分别验证 Vue
与 React 的首页、登录、健康检查和任务列表接口，最后只清理该项目名下的容器和卷。
不要把 `-ProjectName` 指向开发环境或 `worktodo-t10-walk-backend`。

```powershell
pwsh -File scripts/rollback-drill.ps1
# 可选：指定 Compose 文件、独立项目名和前端端口
pwsh -File scripts/rollback-drill.ps1 `
  -ComposeFile docker-compose.prod.yml `
  -ProjectName worktodo-drill `
  -Port 18080
```

#### 通用代码回滚

```bash
# 回滚到上一个版本
cd /opt/worktodo
git log --oneline -5
git reset --hard <previous-commit-hash>

# 重新构建部署

docker-compose -f docker-compose.prod.yml up -d --build
```

## 八、升级维护

### 8.1 版本升级流程

1. **备份数据**
   ```bash
   ./scripts/backup.sh
   ```

2. **拉取最新代码**
   ```bash
   git pull origin main
   ```

3. **执行数据库迁移**
   ```bash
   docker-compose -f docker-compose.prod.yml run --rm backend alembic upgrade head
   ```

4. **重新构建部署**
   ```bash
   docker-compose -f docker-compose.prod.yml up -d --build
   ```

5. **验证服务**
   ```bash
   curl https://your-domain.com/api/v1/health
   ```

### 8.2 维护窗口

- 建议升级时间：凌晨 2:00 - 4:00
- 提前在应用内公告维护时间
- 维护期间显示维护页面
