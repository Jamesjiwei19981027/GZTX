# APP 原生重写总计划（Flutter，iOS + 安卓）

> 编写：2026-10-31。本文件是总控；每个任务包另有可直接粘贴给其他 AI 的任务文件（T00–T10）。

## 一、已定决策

| 决策 | 内容 | 来源 |
|------|------|------|
| 全部原生重写，iOS 与安卓都要 | 不再用“外壳加载网页” | 用户，2026-10-31 |
| 技术路线 | Flutter 一套代码；iPhone 上用 iOS 风格控件，安卓上用安卓风格控件 | 用户选定（AI 推荐），2026-10-31 |
| 状态管理与路由 | 沿用现有 `provider` + `http`，新增 `go_router` 做 5 个 Tab 与页面栈 | AI 建议 |
| 过渡方式 | 现有网页外壳保留为开关（`USE_WEB_SHELL`），原生版通过验收前不删；验收后默认切原生 | AI 建议 |
| 功能口径 | 以当前手机网页版（`frontend/src/mobile/` 及其嵌入的组件）为功能真源，逐页对齐，不新增功能 | AI 建议 |
| 后端 | 本次不改后端；发现接口缺失或不合用，只记录上报，由总控统一在 `main` 处理 | AI 建议 |

## 二、开工前必须解决（阻塞项）

1. **提交现有改动**：工作区有约 250 个未提交文件（后端、网页、文档）。多个 AI 并行时各自用独立分支／工作树，必须有一个包含这些改动的基线提交，否则它们看不到最新后端和网页。——需要用户决定怎么提交。
2. **iOS 编译环境**：本机是 Windows，无法编译和运行 iOS。需要其一：一台 Mac；或云端 macOS 构建（如 GitHub Actions 的 macOS 机器）。真机安装还需要苹果开发者账号。——需要用户决定。在此之前，iOS 风格只能用“截图对比测试”在 Windows 上验证外观，不能验证真机行为。
3. 数据库迁移重复建表问题：已于 2026-10-31 修复（未提交）。

## 三、规模

手机网页版约 2.07 万行、约 90 个页面，分 5 个 Tab（工作、人轴、知识、消息、我的）加 AI 汇报模块；另嵌入了几块电脑版组件（任务列表、仪表盘、工作联系人、个人／项目知识空间）。现有原生 Flutter 旧页面约 4000 行，功能落后，仅人轴画布（`app/lib/work_tree/`，约 3000 行）有复用价值，需评估。

`adapt-*` 开头的十几个“适配页”是演示用的状态页（空状态、断网、字号 200%、深色模式、横屏、键盘遮挡等），原生版**不做成页面**，而是变成每个任务包都要满足的验收条件（见第六节）。

## 五、并行协作规则（发给每个 AI 前务必附上）

1. **分支**：每个任务一个分支 `app-native/Txx-简称`，从同一基线（含 T00 合入后的 `app` 分支）切出；完成后由总控审查合入 `app`，再按仓库规则合回 `main`。
2. **目录所有权**：
   - T00 拥有 `app/lib/core/`、`app/lib/design/`、`app/lib/router/`、`app/lib/main.dart`、`app/pubspec.yaml`。
   - Txx 只能改 `app/lib/features/<自己的目录>/` 和 `app/test/features/<自己的目录>/`，以及自己的 `routes.dart`。
   - 需要改共享部分（加依赖、加公共控件、改接口客户端）时**不要自己改**，在回传报告里写“共享改动申请”，由总控统一加。
3. **不改后端、不改网页**：`backend/`、`frontend/`、`miniprogram/` 一律只读。
4. **功能真源**：每页先读对应的网页源文件（任务文件里给了路径），行为、文案、权限判断逐项对齐；接口以 `http://localhost:8010/docs`（Swagger）为准。
5. **不许假装完成**：回传时分清“代码写完 / 测试通过 / 模拟器实测通过”；没跑过的写没跑过。
6. **提交**：在自己分支上提交，提交信息只署用户本人，不加任何 AI 署名；不推送远端。

## 六、所有任务共同的验收条件

- `flutter analyze` 无错误；本任务新增测试 `flutter test test/features/<目录>` 全部通过。
- 每个页面有组件测试；每个页面至少一张 iOS 风格和一张安卓风格的截图对比测试（golden），在 Windows 上即可生成。
- 适配要求（替代原 `adapt-*` 演示页）：空状态、加载中、加载失败可重试、无权限、断网提示；系统字号放大到 200% 不截断关键文字；深色模式；宽度 320 和 430 不溢出；键盘弹出时输入框不被遮挡；危险操作二次确认。
- 时间：接口一律收发 UTC，界面按本地时区显示（见 `app/test/datetime_contract_test.dart`）。
- 文案全中文，不出现英文残留。
- 安卓模拟器上用测试账号实际走通本任务的主流程，附截图。

## 七、测试环境

- 后端：`docker compose -f docker-compose.yml up -d`，接口在 `http://localhost:8010`，安卓模拟器内用 `http://10.0.2.2:8010`。
- 接口文档：`http://localhost:8010/docs`，右上角 Authorize 登录后可直接调用。
- 测试账号：使用项目 E2E 夹具账号（`backend/scripts/seed_e2e_user.py` 种入，账号见 `frontend/e2e/smoke.spec.ts` 中 `E2E_USER` 默认值）；需要带项目、多角色数据时运行 `backend/scripts/seed_people_axis_joint.py`。
- 安卓模拟器：`Pixel_9_Pro`。注意：Codex 的沙箱会在命令结束时结束它启动的模拟器进程，请在普通终端里启动模拟器。
