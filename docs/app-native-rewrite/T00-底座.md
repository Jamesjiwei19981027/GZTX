# T00 底座（必须最先完成）

> 可直接整段粘贴给执行的 AI。执行前先读 `docs/app-native-rewrite/00-总计划.md` 第五、六、七节。

## 目标

在 `app/` 里搭好原生版的底座，让后续 9 个任务包可以互不干扰地并行开发：目录结构、接口客户端、登录状态、iOS／安卓自适应控件库、5 个 Tab 的路由骨架、测试与截图对比工具。**本任务不实现任何业务页面**，业务页只放占位。

## 范围

- 可改：`app/lib/core/`、`app/lib/design/`、`app/lib/router/`、`app/lib/main.dart`、`app/pubspec.yaml`、`app/test/core/`、`app/test/design/`、`app/test/helpers/`，以及为 T01–T09 预建的 `app/lib/features/*/routes.dart` 占位文件。
- 只读：`backend/`、`frontend/`、`miniprogram/`。
- 保留：`app/lib/screens/web_shell_screen.dart` 与 `app/lib/platform/`（网页外壳，作为开关后备）；`app/lib/work_tree/`（留给 T04 评估）。旧原生页 `app/lib/screens/` 其余文件移到 `app/lib/legacy/`，不再引用，T10 删除。

## 步骤

1. **依赖**：在 `pubspec.yaml` 增加 `go_router`、`flutter_secure_storage`（存令牌）。其他能力型依赖（文件选择、录音、实时通话等）不在本任务加，由对应任务提申请。
2. **目录结构**：
   ```
   lib/core/        api/（接口客户端）auth/（登录态）models/（公共模型）time/（UTC 换算）errors/
   lib/design/      tokens（颜色、字号、间距）、自适应控件
   lib/router/      app_router.dart（5 个 Tab + 各任务 routes 汇总）
   lib/features/    auth work projects axis evidence knowledge reports messages me
   ```
3. **接口客户端**（`lib/core/api/`）：以现有 `app/lib/services/api_client.dart` 为基础迁移，保留并发 401 只刷新一次的逻辑；统一解析后端信封 `{code, message, data}`，业务失败抛带中文 message 的异常，422 解析 `detail`；令牌改存安全存储；基地址用 `--dart-define=API_BASE_URL`。对照网页 `frontend/src/api/client.ts` 行为一致。
4. **登录状态**（`lib/core/auth/`）：当前用户、当前公司、当前项目三个全局状态（`provider`），对照 `frontend/src/App.tsx` 中登录后加载 `users/me`、`companies/mine`、项目列表的顺序。
5. **自适应控件库**（`lib/design/`）：同一个控件在 iOS 上呈现 Cupertino 风格、在安卓上呈现 Material 风格。至少包含：
   页面骨架（导航栏、返回、右上角按钮）、底部 5 Tab、分段切换（iOS 胶囊式 / 安卓下划线式）、列表分组与列表项、输入框（含多行自动增高）、按钮（主／次／危险）、开关、底部弹层、确认对话框（危险操作红色）、日期时间选择器、操作菜单（iOS ActionSheet / 安卓 BottomSheet）、空状态、加载中、加载失败重试、无权限、断网横条、轻提示（toast）、图标集。
   对照网页控件 `frontend/src/mobile/ui/*.tsx`（`AppIcon` 的图标名要全部有对应）。
   页面切换：iOS 从右推入并支持左滑返回；安卓用系统默认转场；安卓返回键规则对照 `frontend/src/mobile/navigation/mobileRoutes.ts` 的返回决策（有未保存内容先确认、有弹层先关弹层、再出栈、Tab 根页退出）。
6. **路由骨架**：`go_router` 的分 Tab 页面栈（切 Tab 保留各自页面栈）；5 个 Tab：工作、人轴、知识、消息、我的。为每个任务预建 `features/<目录>/routes.dart`，只导出一个路由列表和一个占位页，`app_router.dart` 引入全部；后续任务只改自己的 `routes.dart`。屏幕名沿用 `frontend/src/mobile/navigation/mobileRoutes.ts` 的 `REGISTERED_SCREENS`，方便对照。
7. **入口开关**：`main.dart` 默认仍走网页外壳；`--dart-define=USE_NATIVE=true` 时走原生版。
8. **测试工具**（`test/helpers/`）：
   - 假接口：按路径返回固定 JSON 的测试客户端，供各任务写组件测试。
   - 双平台截图对比：一个工具函数，同一页面分别以 iOS 和安卓平台渲染并生成 golden 图（用 `debugDefaultTargetPlatformOverride`）；含中文字体加载，保证截图里中文不是方块。
   - 适配检查工具：320／430 宽度、字号 200%、深色模式下渲染不溢出的断言。
9. **控件展示页**：一个调试用页面，列出全部自适应控件，iOS 与安卓各一张截图。

## 验收标准

- `cd app && flutter analyze` 无错误；`flutter test` 全部通过（含原有测试）。
- 以 `USE_NATIVE=true` 在安卓模拟器启动：能登录测试账号，5 个 Tab 可切换，每个 Tab 显示占位页，切 Tab 后返回原页面栈保留；返回键行为符合第 5 步规则。
- 不带开关启动仍是原网页外壳，行为不变。
- 控件展示页的 iOS／安卓截图各一张，分段切换在两端外观不同。
- 每个 `features/*/routes.dart` 占位存在，且只需修改该文件即可挂载新页面。
