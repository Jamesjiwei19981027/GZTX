# T10 集成验收与切换

> 前置：T01–T09 全部审查合入 `app` 分支。由总控（或指定的一个 AI）执行。

## 目标

把各任务包合成一个完整可发布的原生 APP，完成系统级能力，双平台验收后把默认入口从网页外壳切到原生，并清理旧代码。

## 步骤

1. **合入与冲突**：按顺序合入 T01–T09；处理共享改动申请（依赖、权限声明、公共控件）；统一路由跳转名，检查各 Tab 之间的跳转都通。
2. **系统级能力**：
   - 深链接：邀请链接、通知点开直达对应页面（iOS Universal Links、安卓 App Links）。
   - 推送：先保留站内通知加前台轮询；系统推送（iOS APNs；安卓在国内需要接各厂商通道）单独出方案，由用户决定是否做。
   - 权限声明：麦克风、相机、相册、通知在 `Info.plist` 与 `AndroidManifest.xml` 中的中文用途说明。
   - 应用图标、启动页、版本号。
3. **全量回归**：
   - `flutter analyze`、`flutter test` 全部通过。
   - 以 `docs/product-feature-checklist.md` 和 `docs/full-feature-inventory.md` 为清单，逐页逐按钮在安卓模拟器走一遍，并与网页手机版对比，填写对照表（页面 / 按钮 / 网页结果 / 原生结果 / 是否一致）。
   - iOS：在 Mac 或云端 macOS 上编译，用 iPhone 模拟器走同一份清单；有真机和开发者账号时再做真机安装。
4. **切换**：`main.dart` 默认走原生；网页外壳保留一个版本作为回退开关，下一版本删除。
5. **清理**：删除 `app/lib/legacy/`（旧原生页）；更新 `CLAUDE.md`、`app/README.md` 中“APP 是什么”的描述。

## 验收标准

- 对照表中所有页面“一致”，或不一致项已记录原因并经用户确认。
- 安卓：模拟器全量走通；真机安装一次。
- iOS：iPhone 模拟器全量走通（依赖 Mac／云端环境，未具备则明确标注“iOS 未验收”）。
- 冷启动到可操作时间、内存占用记录在报告里（作为基线，不设硬指标）。

## 必须回传的证据

1. 合入记录与冲突处理说明；2. 测试输出；3. 双平台逐页对照表；4. 安卓与 iOS 截图目录；5. 未完成事项与风险清单。
