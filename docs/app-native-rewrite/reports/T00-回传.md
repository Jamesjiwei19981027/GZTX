## 五、给后续任务的用法说明

完整的开发者指引已写入 `app/lib/design/README.md`，涵盖：
1. **如何发起网络请求**：使用 `context.apiClient` 或 `ApiClient()`，自动处理 `--dart-define=API_BASE_URL`、Bearer 令牌携带、默认 30s 请求超时（抛 `NetworkException`）与 401 单飞续期；后端 `{code, message, data}` 信封自动解包；最终 401 自动清理凭据并登出；异常结构化捕获（`ValidationException`, `ApiException`, `NetworkException`, `AuthException`）。
2. **如何获取与管理全局状态**：使用 `context.currentUser`、`context.currentCompany`、`context.currentProject`；通过 `context.authStateRead.selectCompany()` 或 `selectProject()` 进行切换。
3. **如何注册页面与路由**：在各自目录下的 `features/<模块>/routes.dart` 中追加子路由，命名严格对齐 `REGISTERED_SCREENS`；使用 `AppBackScope(isDirty: ...)` 保障返回拦截；动态导出 `authRoutePaths` 与白名单匹配。
4. **如何写双平台截图与无障碍适配测试**：使用 `testAdaptiveGolden(tester, widget, goldenFileNamePrefix)` 生成 iOS 与 Android 截图；声明 `tags: ['golden']`；使用 `ResponsiveChecker.checkAdaptiveLayout()` 同时校验 Android (Material) 与 iOS (Cupertino) 在 320 窄屏、430 宽屏、系统字号 200%、深色模式下的布局安全性。说明 CI 默认使用 `flutter test --exclude-tags golden` 避免跨平台像素抖动。
5. **原生 Tab 与返回键说明**：再次点击当前 Tab 回到该 Tab 根页的原生平台设计说明；返回键四步裁决（ModalRoute 先关闭弹层、AppBackScope 确认未保存、普通二级页 pop、Tab 根页退出应用）的运行时实现机制。
6. **徽标数说明**：`AppTabBar` 已现成支持 `badges` 参数与 `unreadMessagesCount`，T08 无需改动底座。

## 八、第二次返工记录（交叉审查问题逐项修复）

针对交叉审查（`reviews/T00-pi.md`）反馈的问题，按总控指示逐项修复完成并通过全量验证：

### 问题 1：刷新失败后的最终 401 不清令牌、无全局登出机制
- **怎么改的**：
  1. 在 `app/lib/core/api/api_client.dart` 中增加全局认证过期回调 `void Function()? onAuthExpired;`。
  2. 在 `_request` 中，针对非 `/auth/` 业务路径遇到 401 时，若刷新失败或重试后最终仍是 401，立即执行 `await tokens.clear(); onAuthExpired?.call();`，并抛出结构化 `AuthException('登录已过期，请重新登录', code: 401)`。
  3. 在 `app/lib/core/auth/auth_state.dart` 中绑定 `_api.onAuthExpired`，触发时同步重置会话内存状态（`_currentUser = null`、`_currentCompany = null` 等）并设为 `AuthStatus.unauthenticated`，触发 notifyListeners() 由全局路由守卫自动重定向到 `/login`。

### 问题 2 (P1)：Propagate project-loading failures during bootstrap（项目列表加载异常向上传递与错误状态兜底）

### 问题 3 (P2)：Avoid disposing replaced toast entries twice（轻提示 Toast 防二次 dispose 与安全生命周期）
- **问题说明**：
  `app/lib/design/widgets/app_toast.dart` 当连续弹出两次提示时，前一个提示的 entry 会在第二个提示弹出时被立刻 remove 和 dispose，但前一个提示由 `Future.delayed` 挂起的闭包依然等待执行，时间到后闭包再次对同一个 entry 执行 `entry.dispose()`，触发 Flutter debug 断言：`A disposed OverlayEntry cannot be disposed again.`。此外，在未渲染首帧时调用 dispose 还会触发 `_overlay == null` 移除前断言。
- **怎么改的**：
  1. 在 `app/lib/design/widgets/app_toast.dart` 中引入 `Timer? _activeToastTimer` 追踪活跃定时器；
  2. 弹出新 Toast 时，第一时间执行 `_activeToastTimer?.cancel(); _activeToastTimer = null;`，彻底取消前一个 Toast 的延迟销毁回调；
  3. 销毁旧 entry 时，在 `dispose()` 之前使用防御性 `try { _activeToastEntry!.remove(); } catch (_) {}` 确保即使在首帧未挂载或特殊时序下也已从 Overlay 中摘除，符合 Flutter 的 `assert(_overlay == null)` 要求；
  4. 定时器到期时，双重校验 `if (_activeToastEntry == entry)`，只对依然处于当前活跃状态的 entry 执行移除与 dispose，杜绝已替换 entry 的重复销毁；
  5. 导出测试专用的 `@visibleForTesting resetToastForTesting()`，供测试夹具 tearDown 彻底清理残留状态。
- **用什么测试验证**：
  1. 新增 `app/test/design/app_toast_test.dart` 组件测试：
     - `连续弹两次提示时安全取消旧定时器，旧提示不会被 dispose 两次触发断言`：模拟 400ms 内先后触发 Toast 1 和 Toast 2，时间越过 1100ms（原 Toast 1 到期时点）和 1500ms（Toast 2 到期时点），断言全程无任何 FlutterError 或 Assertion failure，提示安全切换与销毁；
     - `同一帧连续触发多次 showAppToast 不产生断言冲突`：在同一个点击事件中瞬间连续触发 3 次 showAppToast，验证无断言冲突，最终正确展示最后一个 Toast 并按时自动消失。
