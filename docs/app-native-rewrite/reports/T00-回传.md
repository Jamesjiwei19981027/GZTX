## 七、返工记录（总控审查 6 项问题修复）

针对总控审查反馈的 6 项问题，已全部修复完成并通过回归测试：

### 1. (1) iOS 风格 Golden 图中文显示为方块
- **原因分析**：在 iOS 模式下，CupertinoPageScaffold、CupertinoNavigationBar、CupertinoButton、CupertinoListTile 等控件走 CupertinoTheme / DefaultTextStyle 文字样式。在 Windows 测试无 CoreText 回退的环境下，其默认字体族为 `.SF Pro Text`，无法解析中文字形，降级为豆腐块。
- **修复方案**：
  1. 在 `app/test/helpers/golden_test_helper.dart` 中，将测试加载的开源中文字体同时注册到通用名 `NotoSansSC` 以及 Cupertino 默认名 `.SF Pro Text`。
  2. 在 iOS 测试渲染包裹层中，显式配置 `CupertinoTheme` 与 `ThemeData.cupertinoOverrideTheme`，将其 `textTheme`（`textStyle`, `navTitleTextStyle`, `actionTextStyle` 等）的 `fontFamily` 全面设为 `NotoSansSC`，并设置 `fontFamilyFallback: const ['NotoSansSC', '.SF Pro Text']`。
- **验证方式**：重新运行 `flutter test --update-goldens`，重新生成并查看 `component_gallery_ios.png`，导航栏标题“自适应控件展示”、按钮“主按钮/次按钮/危险按钮/加载中”、输入框与列表项所有中文全部清晰完整呈现，无任何方块。

### 2. (2) iOS 与安卓 Golden 图所有图标显示为方块
- **原因分析**：Flutter 测试运行器默认不会自动装载字体资产，导致 `MaterialIcons` 和 `packages/cupertino_icons/CupertinoIcons` 字体未被装载，所有 `Icon` 控件渲染为方框。
- **修复方案**：
  - 在 `app/test/helpers/golden_test_helper.dart` 的 `loadTestFonts` 工具中，读取 Flutter 测试运行期资产中的 `FontManifest.json`，遍历每一个字体族定义，提取全部字体条目并通过 `FontLoader` 统一异步装入 Flutter 测试引擎。
- **验证方式**：在 `component_gallery_ios.png` 和 `component_gallery_android.png` 中，铃铛（bell）、断网（wifi-off）、编辑笔（edit）、清除（cancel）、用户头像（user）、安全盾牌（shield）、日历（calendar）、右箭头（chevron）等全部图标均恢复为清晰的矢量图形。

### 3. (3) 开源中文字体测试资源与 FontManifest 统一加载、失败报错机制
- **原因分析**：此前依赖宿主机 Windows 本地路径 `C:\Windows\Fonts\simhei.ttf`，且加载失败静默 catch 降级，在换机器或 Linux CI 运行时必定失效为方块。
- **修复方案**：
  1. 在仓库内新建测试字体资源目录 `app/test/helpers/fonts/`，内置可再分发的开源中文字体 `NotoSansSC-Subset.ttf`（从 Google Fonts 官方制作的高性能 3900+ 字符子集，涵盖 GB2312 常用一级字与项目代码中出现的全部汉字，文件仅 1.9MB），并严格保留了官方 `OFL.txt`（SIL Open Font License 1.1）开源许可证文件。
  2. 测试中采用相对路径同步读取 `test/helpers/fonts/NotoSansSC-Subset.ttf`。如果字体文件不存在或损坏，直接抛出 `StateError` 中断测试，严禁静默降级。
  3. `FontManifest.json` 图标字体加载过程若有任何解析或载入失败，不进行吞异常处理，直接向外抛出让测试失败。
- **验证方式**：执行单元测试，断开系统字体路径依旧 100% 独立加载仓库资源成功；删除或改名测试字体时测试立即报错失败，符合“加载失败让测试失败”的硬性要求。

### 4. (4) Golden 跨平台测试标签与 CI 跳过约定
- **原因分析**：不同操作系统（Windows、macOS、Linux CI）底层字体光栅化算法与抗锯齿存在像素级差异，会导致跨平台 Golden 像素比对产生误差。
- **修复方案**：
  1. 在 `app/test/design/component_gallery_golden_test.dart` 中，为截图对比测试添加 `tags: ['golden']`。
  2. 在 `app/lib/design/README.md` 第 6 节与第 7 节中明确写明：“Golden 只在 Windows 上生成和比对”的约定，并说明 CI 环境默认执行 `flutter test --exclude-tags golden` 跳过该标签。
- **验证方式**：
  - 执行 `cd app && flutter test --exclude-tags golden`，正常跳过 Golden 像素对比，45 个非 Golden 测试全部快速通过（耗时约 3s）。
  - 执行 `cd app && flutter test test/design/component_gallery_golden_test.dart`，标签正常生效且在 Windows 本地完成基准生成。

### 5. (5) 安卓风格“加载中”按钮内奇怪符号（反引号状字符）排查与修正
- **原因分析**：
  1. `AppButton` 在 `isLoading: true` 且 `onPressed: null` 时，ElevatedButton 被 Material 识别为 disabled 状态，整体底色变成了灰色；
  2. 此时原按钮文字 `label` 完全被丢弃，仅留一个 `CircularProgressIndicator`；
  3. `CircularProgressIndicator` 为 indeterminate 动画，未配置 `backgroundColor`。在测试静态帧渲染时，其进度圆弧仅绘制了 2px 宽、几个像素长的初始微小弧段，在灰色底色上放大呈现为一个反引号（`）状的残缺孤立字符。
- **修复方案**：
  1. 在 `app/lib/design/widgets/app_button.dart` 中，为 `CircularProgressIndicator` 增加 `backgroundColor: fgColor.withValues(alpha: 0.25)` 底色轨道，确保在任何静态帧下都呈现完整的环形圆圈。
  2. 在 `ElevatedButton.styleFrom` 中设置 `disabledBackgroundColor: isLoading ? bgColor.withValues(alpha: 0.7) : null`，让 loading 状态下的按钮保持对应变体的底色特征。
