## 七、登录/注册主流程的实现要点（便于审查）

1. 页面里调用 `AuthApi`（只用不改底座 `ApiClient`），拿到 `access_token/refresh_token` 后由 `AuthFlow` 统一：`tokens.save()` → `authState.bootstrap()`（T00 加载用户/公司/项目）→ `go('/verify?required=email')`。
2. 验证门自己拉 `/users/me/verification`：满足要求直接进入 `/work`，不满足显示绑定表单；拉取失败显示可重试的错误页。
3. 手机提醒：`PhoneReminderPolicy` 严格照抄 `phoneReminder.ts`（首次写入起点、固定七天、关闭不延长、时间回拨重算），`PhoneReminderSession` 保证同一次启动只弹一次。
4. 错误处理：所有接口异常都走 `describeAuthError`，断网给“网络连接异常或请求超时，请检查网络后重试”，服务端错误原样展示后端中文 message，绝不静默吞掉。

**踩到并规避的一个路由坑（对 T02–T09 有参考价值）**：从 `StatefulShellRoute`（`/work`）跳到顶层路由（`/verify`）后，如果同一帧内立刻又切回 `/work`，go_router 17.5 会报 `Duplicate GlobalKey<StatefulNavigationShellState>`。现在验证门用“能出栈就 `pop()`，否则 `go('/work')`” + post-frame 的方式回工作台；登录流程里从 `/login` 进入则是单次挂载，不受影响。

## 八、共享改动申请（3 项，均未自行修改）

### 1.（必须）在 `app/lib/main.dart` 挂载 `AuthGateHost`

不改的话，“已登录但邮箱未验证的老用户打开 APP 直接被验证门拦截”和“手机号未验证用户每次启动提示一次”在真机上不生效（目前只有登录/注册当次流程会走验证门与提醒）。

改动位置：`_WorkTodoAppState.build()` 的原生分支，`MaterialApp.router` 增加 `builder`：

```dart
import 'features/auth/gate/auth_gate_host.dart';

return ChangeNotifierProvider<core_auth.AuthState>.value(
  value: _authState!,
  child: MaterialApp.router(
    // …原有参数不变…
    builder: (context, child) => AuthGateHost(
      router: _appRouter!.router,
      navigatorKey: AppRouter.rootNavigatorKey,
      child: child ?? const SizedBox.shrink(),
    ),
  ),
);
```

改动文件只有两个：`app/lib/features/auth/gate/auth_gate_host.dart`、`app/test/features/auth/auth_gate_host_test.dart`（外加本报告）。未改 `design/`、`main.dart`、`router/`，未改 `pubspec.yaml`、`backend/`、`frontend/`、`miniprogram/`。

### 根因

`MaterialApp.router` 的 `builder` 位于根 Navigator 之外，而 **Overlay 是 Navigator 的子节点、不是 Navigator 的祖先**：

- `builder` 的 context 之上没有任何 Overlay；
- `navigatorKey.currentContext` 是根 Navigator 自身的 element，`Overlay.of()` 用 `findAncestorStateOfType<OverlayState>()` 只向上找祖先，同样找不到 Navigator 自己内部那层 Overlay。

所以 `showAppToast` 里的 `Overlay.of(context)` 抛 `No Overlay widget found`。这个异常发生在 `_runGate` 的 catch 分支里，会直接冒泡出去打断启动链路，提示也弹不出来。已用组件测试在修复前原样复现（堆栈指向 `app_toast.dart:70` ← `_showGateError`）。

### 怎么改

选“在 `AuthGateHost` 内部给 child 套一层自己的 Overlay”这条最简单可靠的路线：

1. `_AuthGateHostState` 持有 `OverlayEntry _hostEntry`，其 builder 返回 `KeyedSubtree(key: _toastHostKey, child: widget.child)`；
2. `build` 返回 `Overlay(initialEntries: [_hostEntry!])`，即 child（含根 Navigator）现在挂在宿主自建的 Overlay 里；
3. `_showGateError` 改用 `_toastHostKey.currentContext`（该 context 就在自建 Overlay 内部，`Overlay.of()` 必然能找到），并以 `navigatorKey.currentContext` 兜底；
4. `didUpdateWidget` 在 `child` 换了新实例时 `markNeedsBuild()`，避免 Overlay 条目里残留旧 child；
5. `dispose` 里先 `entry.remove()` 再 `entry.dispose()`。这里有个容易踩的坑：Flutter 的卸载顺序是**先子树、后父 State**，走到 `dispose()` 时自建 Overlay 已被拆掉，`entry.mounted` 为 false 但内部 `_overlay` 仍非空，若照 `if (entry.mounted) entry.remove();` 写，`dispose()` 会命中 `An OverlayEntry must first be removed from the Overlay before dispose is called.` 断言（本轮实际踩到并在全量测试里暴露，已修正）。`remove()` 在 Overlay 未挂载时会直接返回、不触发重建，因此可以无条件调用。

顺带把类注释里“本任务未挂载”的过时说明改成当前真实挂载方式，并修掉 `_runGate` 里一处排版错位的 `try {`。
