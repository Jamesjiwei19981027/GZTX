## 五、与网页版不一致之处（含理由）

1. **“全部项目”（全盘概览）只做成说明行，不是可选中的项目模式。**
   网页版把“全部项目”当作一个 `id === 'all'` 的当前项目，承载个人跨项目待办/日历总览。原生底座 `AuthState.currentProject` 的类型是 `core/models/project.dart` 的 `Project`（`id` 为 `int`），无法表达 `'all'`；任务约束又要求“切换项目后更新 T00 的当前项目全局状态，不自己另存”。故原生版保留网页版的分组标题与说明文案（“「全部项目」仅作为个人待办与日程汇总，不合并各项目的原始 AI 与人轴上下文。”），但该行不可选中，跨项目汇总仍由工作台（T02）承担。**需要共享改动才能完全对齐（见第六节申请 1）。**

2. **项目归档改为调用真实接口。**
   网页手机版 `MobileProjectSettingsScreen` 的 `handleArchive` 只是 `setMessage('归档申请已提交…')`，没有发任何请求（注释写着“若没有独立归档端点”）。但 Swagger 已有 `POST /projects/{id}/archive`，原生版按二次确认 → 真实归档 → 刷新项目列表 → 展示“项目已归档，已转为只读历史存档”。同理，网页未提供“退出项目”入口，原生版按任务范围补齐 `POST /projects/{id}/leave`（PM 会看到“需先把 PM 转让给其他成员”的提示，与后端 `PM 离开前须先转让 PM` 一致）。

3. **邀请入口按权限隐藏。**
   网页概览页对所有人显示“邀请新成员加入”，点进去再被后端 403。原生版把该入口收敛到后端真实能力：邀请要求 ACL `member.pull`（PM / 超管 / 含该动作的委托），归档要求 `tree.edit_any`。`my-permissions` 未透出 `member.pull`，因此邀请入口只对 PM 与超管显示（委托场景宁可不显示，也不显示点了必然 403 的按钮，见第十节第 4 条）；普通成员直接看不到管理入口——这也是任务验收项“非管理员看不到管理操作”的实现方式。

4. **成员详情的事项来源换成项目维度接口。**
   网页用 `listTasks({page:1,page_size:50})` 拉“我的任务”再按 `project_id` 过滤，非本人任务会漏。原生版用 `GET /projects/{id}/tasks`（page_size=200 分页拉全）再按 `assignees/assignee` 过滤，项目隔离更准确。

5. **在线状态失败不再静默。**
   网页 `listPresence(...).catch(() => ({items: []}))` 把失败吞掉。原生版在成员页展示“在线状态暂不可用（原因），成员列表不受影响”。

6. **邀请链接地址。**
   网页用 `window.location.origin + '/?invite=token'`。原生版用 `INVITE_LINK_BASE`（默认 `http://localhost:8010/`，可用 `--dart-define` 覆盖）拼同样的 `?invite=` 形式；原生内跳转地址为 `/projects/invite/accept?token=`。**正式域名与 iOS Universal Links / 安卓 App Links 的系统级注册属于 T10**，本任务只提供构造与解析（`invite_link.dart`）。

7. **邀请接受的失效口径。**
   网页按 `err.code === 404 || 410` 提示“已失效或已被使用”，但后端实际返回 `422 + 邀请无效 / 邀请已过期`，网页这段分支永远不命中。原生版改为按服务端文案判定（含“过期”/“无效”/“不匹配”），文案沿用网页措辞。

8. **复制邀请链接后的“系统分享”。**
   网页只有“复制链接”。原生版提供复制（真实可用，`Clipboard`），并把系统分享做成**可选注入回调** `onShare`：底座尚未引入 `share_plus`，默认不渲染分享按钮（避免出现点了没反应的假按钮）。依赖合入后由调用方注入即可复用整页。

9. **跨 Tab 跳转用 `push`。**
   概览页“人轴责任链 / 项目知识空间”先 `authStateRead.selectProject(...)`（与网页一致地顺带切当前项目），再 `context.push('/axis' | '/knowledge')`。T00 底座未暴露 `goBranch`，集成时如希望“切 Tab 且保留 Tab 栏”，可按需改为分支跳转。

10. **“删除项目”无对应实现。**

## 七、发现的接口问题（只记录，未改后端）

1. **邀请失效的 HTTP 语义与网页判断不一致**：`POST /projects/invitations/{token}/accept` 对无效/过期邀请返回 **422**（`{"code":42200,"message":"邀请无效"}` / “邀请已过期”），网页按 404/410 判断，故网页该分支永不命中；也意味着“统一信封里的业务 code”只有 `42200`，无法区分“无效”和“过期”，只能靠中文文案区分（不稳健，建议后端给不同 code 或 detail 子码）。

2. **单公司部署模式禁止建第二家公司**：`POST /companies` 在已有公司时返回 `403 40312`。这会直接卡住“新建公司（租户）”页在共享环境中的真机/接口验收；网页与原生端都会原样显示该中文提示（原生端已验证展示逻辑）。

3. **创建项目要求“组织负责人”**：`POST /projects` 仅 `is_org_leader` 可调用（`403 40304 需要组织负责人`），且还要求 License 已开通 `project_tree` 特性、项目配额未满。普通成员在客户端点“新建项目”只会得到该提示——页面已原样透出服务端文案，但**产品上是否需要“申请项目”流程**建议总控确认。

4. **`GET /projects` 的 `page_size` 上限为 100，`GET /projects/{id}/tasks` 上限为 500**：项目列表接口在超多项目时需分页；当前原生端项目列表读的是底座 `AuthState`（`page_size` 未传，默认 20），若某公司项目数 > 20，切换项目页会**看不到第 21 个以后的项目**。这是底座既有实现，我在本任务内未改（属共享代码），建议总控评估是否在 `AuthState` 里补分页。

5. **`GET /projects/{id}` 不返回 `description`**：网页 `BackendProject` 类型里有 `description`，但后端 `_project_dto` 没有该字段，所以项目列表副标题永远是兜底文案“项目协同工作区”（原生端已按此兜底）。若产品需要项目简介，需要后端补字段。

6. **`leave` 对 PM 直接拒绝**：`422 PM 离开前须先转让 PM`。原生端把它做成提示文案，而不是可点的失败按钮（PM 看不到“退出项目”入口），文案与后端一致。

7. **`GET /companies/{id}/presence` 与成员列表是两次请求**，成员与在线状态无法保证强一致（同一秒内可能不一致）。原生端按网页口径接受该最终一致性，并在 presence 失败时降级提示。
