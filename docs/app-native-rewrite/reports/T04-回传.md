### 2. `work_tree` 复用评估结论：**不迁入，按新交互重写**

已阅读 `app/lib/work_tree/`（`work_tree_canvas.dart` 2293 行、`work_tree_layout.dart` 655 行、`work_tree_prefs.dart` 67 行、`work_tree_theme.dart` 107 行）与 `app/test/work_tree_layout_test.dart`（224 行）。结论是不直接搬，原因：

1. **数据模型绑定旧栈**：旧画布依赖 `app/lib/models/models.dart` 的 `TreeNodeItem` 和旧 `AppState` 回调，迁入需要复制/改写 665 行模型与数据适配；任务范围不允许改 `app/lib/models`，复制一份会造成第二套树模型。
2. **布局存储方式与产品冲突**：旧画布把轴向/排序/展开层数存本机 `SharedPreferences`，卡片位置不跨端；产品要求卡片位置走 `/nodes/{id}/layout`、终责位置走 `/projects/{id}/final-owner-position`。直接搬会出现“本机一套、服务端一套”的双写冲突。
3. **交互语义不同**：旧画布是“展开层级/预览卡/双击总览”；新版是“我的职责/项目全貌 + 树序/时间序 + 终责卡固定轴末 + 拖到人上调整上级 + 拖到空白保存位置”，并要接删除预览、委托和权限体系。
4. **旧画布没有拖放合法性**：没有“人挂人可、事项挂人可、人挂事项不可、最多三级、防闭环”的客户端规则，也没有拖动落点提示。

复用的是布局思路（人员走主干、事项挂侧边、时间刻度、终责在轴末），在 `axis_flow_layout.dart` 里重写为可单测的纯函数；旧 `work_tree` 与 `work_tree_layout_test.dart` 保持原样，全量测试中仍通过。

## 六、与网页版不一致之处

1. **无项目状态**（有意修复网页缺陷）：网页人轴无项目时一直转圈并挡住底部 Tab；原生显示“还没有加入任何项目”空状态，可新建项目或刷新，底部 Tab 始终可用（`axis_root_screen_test.dart` 覆盖）。
2. **拖动语义增强**：网页 `MobileAxisGraph` 的拖动只改卡片位置（`applyNodeChanges`），不改上下级；原生把“拖到另一位人员卡上”定义为调整上级（先弹确认，再调 `/nodes/{id}/move`），“拖到空白”才保存位置（`PUT /nodes/{id}/layout`）。这是为了落地验收要求的拖放合法性（人挂人可、人挂事项不可、最多三级、防闭环）。
3. **应用服务端卡片位置**：网页 `MobileAxisGraph` 每次按树重排、不读 `ui_offset`；原生按 `/nodes/{id}/layout` 回填并叠加手动偏移。
4. **终责卡固定轴末**：网页只把 PM 排在轴末；原生在轴末追加“终责”标识，并读取/保存 `/projects/{id}/final-owner-position` 的沿主干偏移；只有 PM/创建者可拖（`axis_canvas_test.dart` 覆盖无权限提示）。
5. **重置布局只重置本地视图**：与网页一致，服务端已保存的 `ui_offset` 不会清除，重新加载后会回来；没有对应清空接口（见第七、八节）。
6. **进度页用真实数据**：网页 `MobileProgressRecordScreen` 是硬编码演示数据（“交互原型评审 70%”“今天 15:20”）；原生读 `/nodes/{id}` + `/nodes/{id}/progress`，按 `recent_records` 倒序显示；无记录时显示“暂无进度记录”。
7. **审计页不造假数据**：网页在 `auditResult` 为空时回退两条假问题（“验收责任未明确”“资料可能不足”）；原生没有结果就显示“本次审计未发现需要处理的责任链风险”。
8. **视图切换控件**：网页用下划线 Tab；原生用底座 `AppSegmentedControl`（iOS 胶囊、安卓下划线），行为与文案一致。
9. **AI 汇报状态文案**：网页是写死的“已收到你的汇报 · 未读”“今天 14:30 已提交”；原生统一为“已收到汇报”“草稿待提交”，不伪造具体时间。
10. **项目选择**：网页用原生 `<select>`；原生用底部选择面板（项目名列表），切换后重新拉取新项目人树（`axis_root_screen_test.dart` 覆盖）。
11. **深链补充查询**：从人轴页跳详情会带 `?projectId=`；外部深链没带时，用 `/users/me/people-axis` 反查所属项目（该接口返回扁平节点），已测。

## 八、发现的接口问题

1. **`GET /nodes/{id}` 缺 `project_id`**（同上）。这是本任务唯一需要绕路的接口缺口；绕路方案已测，但多一次请求。
2. **`GET /delegations` 只返回 `status=active`**（`backend/app/api/v1/delegations.py` 的 filters）。因此列表里的“已撤销”分支在真实环境不可达；测试夹具里放了 revoked 记录仅为验证展示分支，与网页行为一致，但接口没有“查看历史授权”能力。
3. **`GET /nodes/{id}/progress` 不返回节点标题**，进度页要额外调 `GET /nodes/{id}` 才能显示标题；建议把 `title` 放进进度 DTO。
4. **`POST /projects/{id}/axis-audit` 返回的 `nodes[].title` 是节点标题（人员岗位/姓名取决于建节点时写入的 title）**，不是人员姓名；客户端直接展示会在部分数据下显示岗位而非姓名。本任务按返回原样展示，未自行拼接。
5. **`PUT /nodes/{id}/layout` 没有清空语义**，见第七节第 3 条。
6. **`GET /nodes/{id}/deletion-preview` 的 `handover_candidates` 只返回 `{id,title}`**，没有人员姓名/岗位；客户端只能显示 title，交接选择时信息略少。
