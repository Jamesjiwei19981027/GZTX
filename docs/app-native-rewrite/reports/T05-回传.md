## 五、与网页版不一致之处（逐条给理由）

1. **材料详情页改为真实数据**。网页版 `MobileEvidencePackageDetailScreen` 是写死的演示内容（"交互原型评审材料""已提交 · 版本 2"、两个假文件、假汇报引用次数），不请求任何接口。原生按 `GET /evidence/{package_id}` 渲染，并补"材料信息"区（类型/状态/提交时间/编号）。理由：原生版要对齐真源行为，不能把演示数据带上线。
2. **详情页无"引用此材料的汇报"**。后端未提供该关系，网页版是写死文案，原生不展示。
3. **详情页文件点击行为**。网页版文件行无实际动作；原生弹"文件信息"面板并明确说明后端未提供下载/预览接口（见第七节第 1 条），不伪造预览。
4. **提报人名称**。网页版写死"林悦"；详情接口只返回 `submitter_user_id`，原生显示"我"或"用户 #id"（见第七节第 4 条）。
5. **知识草稿页"保存草稿"按钮取消**。网页版该按钮只关闭页面，没有任何保存接口；原生不提供伪保存，改为"返回草稿列表"，并在报告登记（若后端补编辑接口可再加）。
6. **草稿标题/正文只读**。网页版可编辑，但没有任何更新接口，编辑内容不会被保存；原生只读展示，避免让用户以为已保存。
7. **检索页去掉类型过滤 chips**。网页版的"全部/任务/材料/知识"不会真正过滤（后端 `/knowledge/search` 只接受 `q` 与 `top_k`），点了没有效果；原生不提供无效控件。
8. **检索页不预填默认关键词**。网页版默认填"原型验收"并自动检索；原生默认空、点"检索"才请求，避免无意义调用。
9. **检索结果展示真实正文**。网页版结果是写死的示例段落并高亮关键词；原生展示后端 `chunk_text`，来源用"材料 #id / 任务 #id / 知识 #id"（后端未返回标题）。
10. **已发布页不再写死"项目目标/当前里程碑/参考材料"**。原生只渲染真实的已发布知识页正文 + 材料列表；多页时从第二页起用页标题分节。
11. **提交页增加上传进度与失败重试**。网页版只有"正在上传文件…"文案；任务文件要求"大文件上传显示进度，失败可重试"，原生用分块投递汇报进度并提供重试。
12. **提交页增加离线草稿**。网页版材料提交无草稿；任务文件要求断网保留草稿，原生在"网络失败"时保存文字 + 已上传文件，并在重新进入时提示"已恢复上次未提交的草稿"。
13. **语音不可用时的文案**。网页版提示"当前环境无法直接录音…"；原生在未接入插件时明确说"当前安装包尚未集成录音组件（已提交共享改动申请）"，权限被拒时给"系统设置 → 应用 → 权限 → 麦克风"的文字引导 + 重试（一键跳设置需 `permission_handler`，见第六节）。
14. **材料类型仍不手选**。与网页版一致：由文件扩展名推断（`document/figma/commit/log/delivery`），纯文字按"文档"提交。

## 七、发现的接口问题

1. **没有材料文件下载/预览接口（阻塞"文件预览与下载"）**。`GET /evidence/{package_id}` 只返回 `file_id/original_name/mime_type/size_bytes`，全仓没有 `/evidence/files/{file_id}/download`；`/collab/files/{id}/download` 是消息模块的 `CollabFile`，不适用材料。网页版因此用写死文件名糊过去。建议后端补带 company/project ACL 的下载接口，原生再实现预览/下载。
2. **运行环境的数据库缺列，材料相关接口全部 500**。`GET /nodes/1`、`GET /nodes/1/evidence` 返回 `Internal Server Error`，后端日志为
   `sqlalchemy.exc.OperationalError: (sqlite3.OperationalError) no such column: tree_nodes.node_origin`。
   这不是本任务代码问题，但会让「材料提交/详情/责任事项标题」在当前环境全部不可用，也影响 T04。请总控在 `main` 修迁移并重建库后再联调。原生已做降级：标题加载失败回退为"当前责任事项"，不阻塞页面。
3. **`/projects/{id}/llm-wiki` 错误格式与其它接口不一致**。403/503 时返回 `{"detail": "无权查看该项目知识"}`，而不是统一信封 `{code,message,data}`；客户端已兼容两种，但建议统一，否则各端都要写两套解析。
4. **材料详情缺提报人姓名与责任事项标题**。只有 `submitter_user_id`、`node_id`，界面要额外请求 `/nodes/{id}`（当前环境还 500）。建议详情直接返回 `submitter_name`、`node_title`。
5. **知识检索结果缺标题**。`/knowledge/search` 只给 `source_type`、`source_id`、`chunk_text`，网页版靠写死标题补位；建议补 `source_title`（材料名/任务名/知识页名）。
6. **提交返回的 `job_id` 语义依赖部署配置**。只有 `EXTRACTION_MODE=worker` 才真异步，其余模式请求返回时 job 已是终态。客户端统一轮询（2s × 最多 15 次），到上限提示"后台仍在处理"，不会无限转圈；若后端会长时间排队，请告知，我把上限调到与后端 SLA 匹配。
7. **接口实测范围有限**。用夹具账号 `e2e_user` 实测到：`POST /evidence/files` multipart 合同正常（403 "非项目成员，无法上传材料"）、`POST /asr/transcribe` multipart 正常（403 "非本公司成员"）、`GET /evidence/1` 404 信封正常、`GET /jobs/1` 404 信封正常、`GET /projects/1/llm-wiki` 403 detail 格式、`GET /projects/1/knowledge/search` 403 信封正常。由于 `e2e_user` 未归属任何公司（`/companies/mine` 返回空），**未做带真实项目数据的联调**；也未运行 `seed_people_axis_joint.py`，避免往共用库写数据影响其它任务。
