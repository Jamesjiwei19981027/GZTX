## 五、与网页版不一致之处

逐条对照 `frontend/src/mobile/features/reports/` 对应源文件：

1. **输入框弹性自适应与键盘滚动避让**：
   - 网页版在手机输入长文案时高度固定容易滚动受限，点击快速添加时偶发键盘遮挡输入框。
   - 原生版采用 `maxLines: null` + `Scrollable.ensureVisible` + 键盘安全边距监听，随着文字录入自动增高，软键盘升起时自动将光标所在行滚动到视口中上方。
2. **草稿隔离安全机制**：
   - 网页版将草稿存放在浏览器本地（按项目切），切换登录账号时若未显式清理容易造成串号。
   - 原生版采用 `(userId, projectId)` 复合键强隔离，退出登录时自动清空对应用户的草稿，彻底杜绝数据交叉。
3. **字号 200% 极端无障碍防护**：
   - 网页版在高倍率字体缩放时底部双操作按钮（如“暂存草稿 / 提交汇报”）容易换行或溢出父容器。
   - 原生版在底部操作栏采用 `FittedBox(fit: BoxFit.scaleDown)` 弹性包裹，保证极端大字号下按钮文字不撑破屏幕。
4. **提交后草稿清除的防死灰复燃**：
   - 页面销毁（`dispose`）时通常有防抖定时器自动暂存草稿，原生版增加了 `_submitted` 门控状态，当提交成功触发页面弹出时，绝对不会被退出事件再次将已提交的旧文本写回草稿。

## 七、接口问题与后端设计建议

对照真实后端 Swagger（`http://localhost:8010/docs`）与 `backend/app/` 接口实现，发现以下接口缺口与兼容性细节：

1. **G01 智能体汇报送达状态缺口**：
   - 目前后端提交汇报（`POST /reports/`）仅持久化了汇报记录，但对于方案中规划的“沿人轴逐级向上推送至直属领导智能体与总领导智能体”的流转回执和送达确认时间戳，后端尚未提供独立的节点查询接口。
   - 原生端当前根据汇报 `status`（如 pending、submitted、reviewed）在客户端按直属领导与领导层关系进行状态节点渲染，并给出“AI送达由后台智能体调度，暂无独立回执”的诚实降级提示。建议后端在汇报表中增加 `delivery_path` 或 `audit_log` 字段。
2. **直属领导自己汇报给自己拦截**：
   - 后端在接收汇报时未对 `leader_id == user_id` 做严格的业务校验，可能导致用户误将自己选为领导陷入死循环。
   - 原生端已在前端进行硬性校验：`reportCapabilities.canSubmitToLeader` 拦截并明确红字提示“直属领导不能是自己”，建议后端也在接口层面增加 422 验证抛错。
3. **接口英文报错信息本地化**：
   - 后端部分错误码返回为纯英文（如 `"Report already submitted"`、`"Leader not found"`）。
   - 原生端数据层已全部实现映射转换，统一以地道、亲切的中文向用户呈现，防止英文错误穿透到 UI。

## 八、第一次返工记录（Codex 评审修复）

本轮返工针对 Codex 审核提出的 6 项缺陷进行了逐项深入修复并补全回归测试，全部修复严格限制在 `app/lib/features/reports/` 与 `app/test/features/reports/` 范围内：

### 1. (P1) 切换项目时路由参数未同步更新且项目名不一致
- **问题**：在 `/reports/create?projectId=10` 等带 `projectId` 参数的路由下切换到新项目时，此前仅更新了 `AuthState` 登录态，路由 query 参数仍为旧项目 ID，导致页面数据与项目名不一致，提交时也会提交到错误项目。
