## 五、与网页版不一致之处（有意差异，均已在上文说明理由）

1. **外观与语言**：网页有中/英切换；原生按交付约定全中文，页面保留"显示语言：简体中文 / 其他语言暂未开放"说明，不做假切换。
2. **主题档位**：网页只有浅色/深色；原生增加"跟随系统"（任务文件要求），并**真正持久化**（本地 `SharedPreferences` + 服务端 `ui-prefs.theme_mode`）。
3. **字号**：网页只是展示系统 Dynamic Type 数值；原生提供"跟随系统 / 标准 / 大 / 特大"四档并本地持久化（服务端 `ui-prefs` 无字号字段，见第七节）。
4. **管理员入口可见性**：网页对所有人显示"企业集成与管理"分组（普通成员看到只读横幅，且其 `mapUser` 恒返回 `role:'成员'`，`isUserAdmin` 实际恒为 false）；原生按任务要求**只对超级管理员显示入口**，无权限直接访问显示无权限态。
5. **管理员 SMTP / LLM 接口**：网页管理页误用**个人**接口 `PUT /notifications/smtp-config`、`/notifications/llm-config`；原生改用**企业级** `PUT /companies/{id}/smtp`、`/companies/{id}/llm`（服务端 `require_super_admin` 校验），语义正确。
6. **单点登录配置**：网页 `handleSave` 只做 `setSaved(true)`，**不发任何请求**（假保存）；原生不提供假保存，改为真实开关 `PATCH /companies/{id}/login-methods`（OIDC）+ 只读参数清单，并说明后端无参数写入接口。
7. **推送证书状态**：网页写死"生产证书有效期至 2027-08-30""FCM v1 接口正常"等伪数据；原生只展示真实的 WebPush 公钥状态（未配置时后端 503 → 显示"待配置"+原因），APNs/FCM 标注"无查询接口"。
8. **第三方服务绑定**：网页"前往绑定"是 `alert()` 提示；原生展示真实 `wx_bound`/`subscription_enabled` 并可在已绑定时开关订阅（`PUT /wx/subscribe-preference`），未绑定时开关禁用并说明原因。
9. **个人语音识别**：网页管理页把 ASR 配置写到企业级 `bindings/asr`；原生区分企业级（管理员页 `PUT /companies/{id}/bindings/asr`）与个人偏好（`PUT /users/me/bindings/asr`）。
10. **任务默认值**：网页用固定分类名（Work/Personal/Documentation/Shopping/Health）；原生使用后端真实的 `GET /categories` + `ui-prefs.task_default_category_id`，无分类时只保存优先级并提示。
11. **注销账号**：网页 2 重（密码 + 关键字）；原生 3 重（密码 + 关键字 + 不可逆确认弹窗）。
12. **我的首页"我的知识空间"入口**：原生未放入本页（知识归属 T06 的知识 Tab，避免跨模块跳转；如需保留请总控裁定）。
13. **登录设备**：网页无该能力；原生给出本机平台/账号/会话状态 + 明确说明服务端无设备列表接口。

### A2 底座缺陷：`AppButton` 长文案 + 200% 字号溢出
`app/lib/design/widgets/app_button.dart:116` 的 label `Row` 没有 `Flexible`，在 320 宽 + 200% 字号时溢出（实测溢出 52px）。建议把 label 包 `Flexible(child: Text(..., textAlign: center))` 或允许换行。本任务已把两个超长按钮文案缩短（"保存 SMTP 配置"→"保存配置"、"更新密钥并加密入库"→"保存密钥"）规避，但这是全局隐患。

### A3 底座缺陷：`AppErrorState` / `AppEmptyState` 文字颜色写死浅色
两者标题/正文使用 `AppColors.textPrimary/textSecondary`，深色模式下不可读。本任务在 `me_common.dart` 自建 `MeErrorState` 规避；建议底座改为按 `isDarkMode(context)` 取色。

### A4 `Company` 模型缺 `my_membership`
`/companies/mine` 与 `/companies/{id}` 都下发 `my_membership.is_super_admin`，但 `app/lib/core/models/company.dart` 未解析。本任务在 T09 内额外请求 `GET /companies/{id}` 判定权限；建议 `Company.fromJson` 补 `isSuperAdmin`，各任务共用，减少重复请求。

### A5 头像选图依赖
`app/pubspec.yaml` 需新增 `image_picker`（iOS 还需 `NSPhotoLibraryUsageDescription` / `NSCameraUsageDescription` 权限描述）。本任务已把上传与错误处理全部写好，`MeProfileScreen(pickImage: …)` 只需由宿主注入选图实现。

### A6 `ApiClient` 不支持 multipart
头像上传目前自行用 `http.MultipartRequest` 组包（含超时与错误映射）。建议底座提供 `upload(path, bytes, filename)`。

## 十、第一次返工记录

返工前先核对后端真实契约：`companies.py::put_company_llm` / `services/llm_settings.py::save_company_llm`（单套生效配置、api_key 空串不改、未识别 provider 归 `custom`、显式空串地址会保留）、`org.py::_integration_dto`（只有 `config` / `has_credentials` / `last_sync_at` / `created_at`，没有 `enabled` / `status`）、`org.py::trigger_org_sync`（`provider` 是 query 参数，缺省取最新一条集成账号）。

### 1）[P1] 模型密钥页覆盖生效配置

- **问题**：`/companies/{id}/llm` 只有一套生效配置；原页面让管理员用 OpenAI 公司选“DeepSeek”存密钥，只提交了 `provider` + `api_key`，后端把 `deepseek` 归为 `custom`，却继续沿用 OpenAI 的地址与模型，保存成功但全公司 AI 调用失效。
- **怎么改**：`admin_model_keys_screen.dart` 删除前端自造的 openai/deepseek/claude 三选一，只展示当前生效配置的厂商（名称取后端 `presets[id].label`）、地址与模型；保存时**只提交 `api_key`**，`provider` / `base_url` / `model` 一律由服务端沿用。当前为 `fake` / `ollama`（`presets.needs_key=false`）时提示无需密钥并隐藏密钥输入；页脚明确“换厂商请到「AI 模型配置」页同时改地址与模型”。不再提供后端不支持的 deepseek / claude 选项。
- **测试验证**：`me_admin_test.dart::模型密钥：只轮换当前生效配置的密钥，不提交厂商/地址/模型`（断言 PUT body 只有 `api_key` 一个键、页面无 DeepSeek/Claude 选项）、`模型密钥：当前为本地桩时提示无需密钥`、既有 `模型密钥：留空时提示且不发送请求`。

### 2）[P2] 深色模式 / 字号冷启动不生效

- **问题**：`MeScreenAppearance` 直接读单例渲染，唯一的生产侧 `ensureLoaded()` 在 `MeAppearanceScreen._init` 里；冷启动直接进「我的」首页时读到的是默认值，必须再打开外观页才生效。
- **怎么改**：把 `MeScreenAppearance`（T09 所有页面与路由共用的包装）改为 `StatefulWidget`，在 `didChangeDependencies` 解析出控制器后，若 `!isLoaded` 就 `ensureLoaded()`，加载完成经 `ListenableBuilder` 自动重绘。**未改 `main.dart`**，因此不需要新的共享改动申请。新增 `MeAppearanceController.resetInstanceForTest()` 并用测试夹具每个用例重建单例，避免 FakeAsync 跨用例复用未完成的加载 Future。
- **测试验证**：`me_appearance_test.dart::外壳仅跟随系统时保存的深色/字号仍需在冷启动生效`（预置 `me.appearance.theme_mode=dark`、`text_scale=1.3`，重置单例后直接 pump `MeRootScreen`，断言单例已加载、`Theme.brightness == dark`、`MediaQuery.textScaler.scale(10) == 13`）。`me_adaptation_test.dart` 全量通过，确认改动未引入跨用例挂起。

### 3）[P2] API 地址留空提交空字符串

- **问题**：`AdminLlmConfigScreen._save` 把输入框内容 `trim()` 后直接提交；后端 `save_company_llm` 对显式空串原样保留，配置存下来却 `is_usable()==false`，AI 调用回退到环境变量 / fake。
- **怎么改**：提交前先取 `_config.presets[provider].default_base_url` 补默认地址；预设也没有默认地址（如 `custom`）时前端拦截并提示“请填写 API Base URL（当前提供商没有内置默认地址）”。字段提示改为“留空则使用该提供商的内置默认地址；没有默认地址时必须填写”；切换厂商时对仍为空白的地址/模型自动填入该厂商预设值；保存成功回填服务端返回的地址。
- **测试验证**：`me_admin_test.dart::AI 模型配置：API 地址留空时按厂商预设补默认地址`（断言 PUT body `base_url == https://api.openai.com/v1`）、`AI 模型配置：没有默认地址时必须手填地址`（断言提示出现且未发请求）、`AI 模型配置：切换厂商时地址与模型一起换成该厂商预设`（切到 OpenAI 兼容后断言 `provider` / `base_url` / `model` 成套提交）、既有 `模型名称为空时前端拦截` / `密钥留空时不提交 api_key`。

### 4）[P2] 组织同步未指定 provider

- **问题**：`POST /companies/{id}/org-sync` 不带 `provider` 时后端取 `IntegrationAccount` 最新一条；SMTP / LLM 也写在这张表，管理员配过 SMTP 或 LLM 后同步会选中非组织账号并报“不支持的厂商”。
- **怎么改**：`MeApi.triggerOrgSync(companyId, {required String provider})` 改为必传并把 `provider` 放进 query；`AdminOrgSsoScreen` 从 `listIntegrations` 结果里挑选可同步账号（`wecom` / `dingtalk` / `feishu` / `generic_scim` / `generic`，`oidc` 明确排除），优先 `isConfigured` 的账号；没有可用账号时禁用“立即同步”并提示先去配置。
- **测试验证**：`me_admin_test.dart::组织与登录集成：触发同步与切换登录方式`（断言请求 `queryParameters['provider'] == 'wecom'`）、`组织与登录集成：没有可同步厂商时禁止触发同步`（仅返回 oidc 时按钮禁用且不发请求）。

### 5）[P2] 集成配置状态误判为“待配置”

- **问题**：`MeIntegration` 读的是后端并不存在的 `enabled` / `status`，恒为 false/空串，所有已配置的企微、钉钉、飞书都显示“待配置”。
- **怎么改**：按 `org.py::_integration_dto` 真实字段重写模型：`has_credentials`、`config`、`last_sync_at`、`created_at`；新增 `isConfigured = hasCredentials || config.isNotEmpty || lastSyncAt != null` 与 `supportsOrgSync`。页面上有同步记录显示“已同步”（成功色），已配置显示“已配置”，只有空壳账号显示“待配置”；副标题按真实时间显示“上次同步 …”或“配置于 …（尚未同步）”。测试夹具改为与后端一致的字段，不再出现 `enabled` / `status`。
- **测试验证**：`me_admin_test.dart::组织与登录集成：按真实字段展示配置状态`（有凭证+同步时间的企微显示“已同步”“上次同步”，空壳钉钉显示“待配置”），夹具 `me_test_harness.dart` 的 `/companies/1/integrations` 已按 DTO 重写。
