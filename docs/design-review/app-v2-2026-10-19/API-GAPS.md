# APP V2 接口与能力缺口清单 (API-GAPS)

> 创建于 T00 基线核验阶段。依据 `docs/superpowers/plans/2026-10-19-app-v2-ui-gemini.md` 第 4 节及现有前后端源码分析。
> 原则：严禁假成功、假数据冒充真实数据；缺少接口或依赖时，前端展示真实状态并在实施跟踪表中标记“依赖阻塞”。

---

## 缺口分类概览

- **G01 AI 接收 / 已处理回执**：影响页码 38、40、95
  - **现状依据**：`backend/app/models/report.py` 和 `backend/app/api/v1/reports.py` 中有 `status`（draft/submitted/read/archived）、`read_at` 等，但没有 AI 已阅读 / 执行完成的通用回执字段。AI 智能体 session 交互与报告提交相互解耦。
  - **所需契约**：报告关联的 AI 响应流水、AI 确认处理回执字段及相应查询接口。
  - **UI 处理**：提交与送达页显示“已送达直属领导（状态：已提交 / 已读）”，AI 状态展示“状态暂不可确认”，不虚构四个全绿成功节点。
  - **负责端**：后端接口扩展 / 前端状态适配。
  - **当前状态**：前端已防御完成（T08/T09），后端待提供独立回执字段。

- **G02 草稿独立保存与不可变历史版本**：影响页码 37、39
  - **现状依据**：`frontend/src/api/reports.ts` 支持 `generateMyReportDraft()` 和直接提交，但没有独立持久化临时草稿、多版本对比与撤回历史的接口。
  - **所需契约**：草稿持久化存储接口、版本快照不可变记录接口（`GET /reports/{id}/versions`）。
  - **UI 处理**：本地草稿采用客户端基于 `userId + projectId + formKind` 隔离暂存；历史详情展示真实提交记录，不假造多版本树。
  - **负责端**：后端历史版本能力 / 前端本地草稿保护。
  - **当前状态**：前端隔离暂存已落地（T08），不可变提交记录回显正常。

- **G03 汇总后正式发布闭环**：影响页码 42
  - **现状依据**：后端支持 `POST /reports/projects/{project_id}/aggregate` 生成项目汇报封装，但未提供“管理者审核确认后正式发布并落库不可变归档”的工作流接口。
  - **所需契约**：`POST /reports/projects/{project_id}/publish` 或审核发布审批流。
  - **UI 处理**：提供“生成项目汇总”能力，展示聚合内容；发布按钮标记为“当前支持生成与查看汇总”，不假造发布已入库成功。
  - **负责端**：后端发布审批流。
  - **当前状态**：前端汇总生成已接通（T09），发布审批流保持依赖说明。

- **G04 上级追问闭环**：影响页码 49、99
  - **现状依据**：系统具有站内通知与会话回复，但无针对报告特定字段的上级差异追问工单、整改闭环与审计记录。
  - **所需契约**：报告追问记录与处理状态流转接口。
  - **UI 处理**：可通过关联通知发送站内消息，页面清晰提示“通过消息发送沟通”，不伪造独立追问工单已闭环。
  - **负责端**：后端报告互动流。
  - **当前状态**：前端页面结构与追问引导已实现（T09），等待工单模型支持。

- **G05 差异确认与核验决定持久化**：影响页码 41、100
  - **现状依据**：项目资料对照中可以展示 `conflicts` 与 `task_snapshot`，但无管理者对差异进行“人工核验通过/驳回”持久化决定的写接口。
  - **所需契约**：`POST /reports/projects/{project_id}/conflicts/{conflict_id}/resolve`。
  - **UI 处理**：清晰展示比对数据与冲突项，核验按钮保留并提示“核验记录需后端持久化支持”，不伪造保存成功。
  - **负责端**：后端冲突裁决模型。
  - **当前状态**：前端资料对照与核验交互已实现（T09），裁决持久化保持说明。

- **G06 直属 / 全部下属与过期统计**：影响页码 06、40
  - **现状依据**：管理者的汇报列表仅包含其具有查看权限的汇报记录，不能客户端抓取全员资料计算。
  - **所需契约**：下属汇报统计与过期未报汇总接口。
  - **UI 处理**：仅统计服务端返回的真实可见汇报数据，无数据项展示“暂无记录”。
  - **负责端**：后端统计聚合接口。
  - **当前状态**：已有部分支持，待完善聚合。

- **G07 APP 原生推送、音视频通话与文件选择**：影响页码 26、45—47、57、90、91
  - **现状依据**：`backend/app/api/v1/calls.py` 有信令端点，但需要 WebRTC/TURN 服务及原生权限配合；原生推送需要 APNs/FCM 凭证；WebView 内文件上传需宿主支持。
  - **所需契约**：Flutter 宿主权限桥接、TURN 服务配置、推送证书绑定。
  - **UI 处理**：通话页面未配置时明确提示“需配置 TURN 语音服务”；上传使用标准 input 或宿主通道。
  - **负责端**：移动宿主 / 运维配置。
  - **当前状态**：待核实 / 依赖阻塞。

- **G08 公司管理 / SSO / ASR / 存储的移动端封装**：影响页码 10、60、61、92—94
  - **现状依据**：后端有 `sso.py`、`org.py`、`bindings.py`，但前端 `api/` 缺少对应移动封装，且普通成员无权限操作。
  - **所需契约**：前端 API 增加对现有后端路由的准确调用封装。
  - **UI 处理**：普通成员隐藏或仅显示只读说明，管理员通过真实角色判定展示。
  - **负责端**：前端 API 封装与权限控制。
  - **当前状态**：已有后端接口，需补全前端封装。

- **G09 本地草稿、原生字体 / SafeArea / 返回桥接**：影响页码 67、73、74、78
  - **现状依据**：现有 Web 页面缺乏离线断网恢复和系统的统一返回协调机制。
  - **所需契约**：客户端本地 IndexedDB/LocalStorage 状态隔离，Flutter 与 React 的原生桥接。
  - **UI 处理**：在 T01-T03 中作为前端/宿主核心能力全部实现并实测验证。
  - **负责端**：前端移动基座与 Flutter 宿主。
  - **当前状态**：进行中（T01-T03 实施）。

- **G10 外部服务配置依赖（真实模型、短信/邮箱验证码、微信、TURN）**：影响页码 01—04、17、31、33、36、37、43、46、50、59—61、63、79、90—94
  - **现状依据**：外部 SMTP、大模型 API Key、ASR 语音服务、微信公众平台等需要部署环境真实提供。
  - **所需契约**：外部服务密钥与真实网络连通。
  - **UI 处理**：未配置或调用失败时，展示真实错误原因（如“未配置 LLM 模型”或“邮箱服务暂未配置”），提供重试与配置指引，严禁假成功。
  - **负责端**：系统运行环境。
  - **当前状态**：环境依赖 / 真实错误展示。
