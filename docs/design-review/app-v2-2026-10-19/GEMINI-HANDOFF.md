## 核心约束

- 默认运行入口是 `app/lib/screens/web_shell_screen.dart` 加载 `frontend/`，不是旧 Flutter 原生页面。先把生产默认入口改好。
- 保留人轴作为人员、岗位、上下级、事项和权限事实来源；AI 附着在项目内协助汇报。
- 每个项目的智能体、对话、草稿、材料与检索隔离；总领导接收项目摘要封装。
- 汇报提交后，在人轴与消息中提示，直属领导及其 AI 的状态只能按真实服务端记录显示。
- 不改变后端权限、数据模型和 API 语义来迁就图片。发现缺口，记录所需请求 / 响应、受影响页、UI 处理及验证状态。
- API 不支持的动作不得只 `setState`、弹成功提示或写本地状态后冒充已完成；相关页保留真实说明并在跟踪表标“依赖阻塞”。
- UI API 调用继续复用 `frontend/src/api/`；保留 token refresh、错误码、任务来源、时区、上传限制及版本来源。
- 当前工作区已有大量跨端未提交改动。先记录状态、辨认归属；禁止 reset、clean、自动 stash、覆盖他人文件或 `git add .`。
- 不删除 / 修改 `D:\Android\avd` 文件，不重建 AVD，不升级 / 降级 Android SDK，不直接运行 QEMU 诊断 DLL。正常关闭模拟器只用 `adb -s emulator-5554 emu kill`。
- 每个任务交付变更文件、实测结果、截图和剩余缺口。全部页面的基准是“能到达、能操作、状态真实、权限正确、布局可用”。
