# APP V2：iOS 风格与平台适配补充规范

版本：IOS-ADDENDUM-R1，2026-10-19。用户已批准原 100 张设计图，并授权增加 iOS 风格优化、交由 Gemini 实现。本补充保留页面编号、业务流程、品牌蓝和五个主导航，供同一次 UI 实施使用；它不是 iOS 实测记录。

## 1. 实现目标

同一套业务状态与组件，在 iOS 上采用符合平台习惯的导航、字体、列表、弹层与操作反馈，在 Android 上保留相应系统行为。默认运行架构仍为 Flutter WebView + React 移动 UI。旧 Flutter 原生壳保留兼容，不作为本次重写的主入口。

### 视觉基准

- 品牌色保持 `#0058BE`；浅色背景采用系统分组列表观感，深色背景与内容区使用语义变量。
- 普通页面顶栏使用紧凑的居中标题；返回按钮采用左侧 chevron，必要时带简短上页名称。
- 工作、AI、我的等根页可在内容区使用 28 的根标题；不与顶栏重复展示同一大标题。其余页面沿用已批准的 22 级标题层级，iOS 紧凑导航标题基准为 17。
- 工作、任务、设置等使用分组列表、内嵌分隔线、适量留白；人员关系和项目风险保留可辨识的结构。
- 内容区保持实色与清晰对比。导航层的轻微半透明仅在可读性和性能满足时启用，减少透明度设置下使用实色。玻璃特效不是本轮验收要求。
- 不将审核图中的时钟、状态栏、手势横条、示例头像或页面编号作为真实 APP 业务 UI 绘制。

## 2. 导航与返回

**适用：所有页面，重点 05、06、12、20、35、44、53。**

- 五个根 Tab 顺序固定：工作、人轴、AI、消息、我的；图标与文字一起显示，选中态清楚，消息角标可被读屏理解。
- 每个 Tab 保留自己的页面栈、筛选条件和滚动位置。切 Tab 不应重新创建同一个任务或丢弃编辑内容。
- Tab 栏是全局主导航；在普通详情页继续可达。独立全屏编辑、通话或确认流程可以暂时隐藏，完成后回到原上下文。
- iOS 详情支持系统边缘返回手势；Android 系统返回、Web 浏览器返回与页面返回按钮遵循同一栈语义。
- 返回优先关闭最上层对话框 / Sheet，再退出当前详情，最后才到根页。根页不凭空制造返回记录。
- 表单未保存时，通过明确的“继续编辑 / 放弃修改”选择保护内容；不能先丢草稿再弹确认。
- 人轴画布平移与 iOS 边缘返回要分别处理：画布内部平移，系统边缘返回仅在确有可返回页面时生效。不能同时让 JS 和 WKWebView 对同一次手势退两层。
- WebView 壳不再额外绘制第二套顶部标题和底部导航。Flutter 负责系统宿主行为，React 负责业务导航 UI。

Apple 的导航与模态指导强调主导航层级、返回和关闭的语义；Flutter 原生路由的自动平台适配不会自动替 React 页面实现这些行为。[Apple 导航设计](https://developer.apple.com/videos/play/wwdc2022/10001/)、[Flutter 平台适配](https://docs.flutter.dev/ui/adaptive-responsive/platform-adaptations)

## 3. Sheet、操作菜单和确认

**适用：07、11、13、16、23—26、29、38、70、82—84、87、88、96。**

- 项目选择、任务筛选、日期选择、节点预览等短流程使用底部 Sheet，展示拖拽把手、标题和明确关闭入口。
- 半屏高度放不下时扩展为大 Sheet；不将长表单强塞到半屏。任务编辑、汇报编辑、Wiki 编辑使用全屏或足够大的编辑面板。
- 同一时间只存在一个可交互的模态层。Sheet 内的多步选择通过局部导航完成，避免层层堆叠。
- 表单使用“取消 / 保存”或“取消 / 提交”；查看详情使用返回。返回与关闭不能在同一状态下含义相反。
- 删除、撤销授权、退出等使用清楚的动作名称与独立取消项。账号删除保留当前密码校验及影响说明。
- iPad 短选项菜单可用 Popover；锚点必须对应触发控件，窗口变小时退化为 Sheet。
- 下拉关闭触发表单脏状态检查；提交中防止重复提交，关闭策略与请求结果保持一致。

以上遵循 Apple 对聚焦任务、单一 Sheet 和长编辑流程的建议。[Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)、[Modality](https://developer.apple.com/design/human-interface-guidelines/modality)

## 4. 字体、图标和点击区域

### 逻辑尺寸基准

- iOS 正文基准 17，Android / 移动网页正文基准 16；主要列表内容 15—17，辅助信息 12—13，Tab 标签基准 12。
- 导航标题 iOS 17 / Android 18；内容区标题 22；根页大标题可为 28。以上为设计基准，不是对用户大字体设置的上限。
- UI 以 CSS 逻辑像素 / Flutter 逻辑尺寸计算，不乘设备 DPR。DPR 仅用于清晰的资源输出和截图。
- 大小依用途分级：行内图标 18—20，常规操作 22，Tab 22—24。内容相关的图标随相应文字适度调整；装饰图形不随屏幕宽度无限放大。
- 统一主要点击目标至少 48 × 48 逻辑尺寸。视觉图标可小于点击区域；小图标不等于小按钮。

### 字体来源与图标组件

- iOS 使用系统字体栈 `-apple-system, BlinkMacSystemFont, 'PingFang SC', sans-serif`；不下载、打包或跨平台分发 San Francisco 字体文件。
- Android / Web 可沿用已自托管字体。首次加载、弱网和离线回退时仍须显示中文。
- Web 业务图标通过单一 `AppIcon` 组件使用仓库已有 `lucide-react` SVG。iOS 返回 / 关闭等可提供平台变体，但含义与组件接口一致。
- Flutter 系统控件可使用已有 `cupertino_icons`。Web 不依赖“安装 SF Symbols 字体”显示图标。
- 所有操作图标提供可访问名称；装饰图标使用 `aria-hidden`。未读状态包含可读文字，不只依赖颜色或红点。

### Dynamic Type 与字号桥接

1. Flutter 从 `MediaQuery.textScalerOf(context)` 读取当前文本缩放；按 body、caption、navTitle、displayTitle 分别计算逻辑尺寸。
2. 将语义字号通过受限宿主桥接传给 React；不把单一线性比例当成所有系统文本样式的真实缩放。
3. React 用语义 token 更新字号。确认 WebView 的平台文字缩放是否已经生效，确保只应用一次，避免双倍放大。
4. 字号或系统显示设置变化后重新发送运行环境。正在编辑的输入与当前页面保持。
5. 保留用户缩放能力，不设置 `user-scalable=no`，不通过强制 `textScaleFactor=1` 或缩小字体来消除溢出。
6. 150%、200% 的设计图用于布局参考。iOS 最终需覆盖真实辅助功能字号类别，不能把 CSS 模拟当成 Dynamic Type 验收。

Dynamic Type 会影响文字和布局；系统字体与可缩放文本样式应一起使用。[Apple Dynamic Type](https://developer.apple.com/videos/play/wwdc2024/10074/)、[自动缩放字体](https://developer.apple.com/documentation/uikit/scaling-fonts-automatically)

## 5. 安全区域与键盘：明确唯一责任方

采用以下默认责任划分，减少双重留白和重复键盘补偿：

- **APP 内：Flutter 负责系统 SafeArea 和键盘导致的 WebView 可用高度变化。** React 内容视口已位于安全区域内，APP 模式不再重复加入相同上下 inset。
- **普通浏览器：网页负责 `env(safe-area-inset-*)` 和可视视口变化。** 使用可用视口布局，必要时读取 `visualViewport`。
- 平台环境中明确 `safeAreaOwner: 'native' | 'web'`；不能同时对同一 inset 使用 Flutter Padding、CSS env 和 JS 补偿。
- Native `Scaffold` 的键盘缩放策略由同一宿主组件统一设置；Web 只根据已经变化的可视区域滚动输入框，不再叠加完整原生键盘高度。
- 全屏编辑保留取消和提交；键盘打开时，主要提交操作保持可达。聊天输入框跟随可视区域，历史内容正常滚动。
- iPhone 刘海 / Dynamic Island、底部手势区、横屏、iPad 分屏及外接键盘都列入最终验证。
- 宿主与网页共享浅深色背景；安全区背景不能在深色模式下出现突兀白条。

最终实现需根据实际 WKWebView / Android WebView 行为验证责任边界，不用固定 34、44、88 等设备特定数字代替系统 inset。[Apple 布局与安全区域](https://developer.apple.com/design/human-interface-guidelines/layout)

## 6. 输入、反馈与动效

- 邮箱、手机号、密码和验证码采用合适的键盘类型、自动填充与可访问标签；允许系统文字选择、粘贴和输入法组合输入。
- 长按菜单、文件选择和授权提示保持平台习惯。点击上传不默认请求相机、麦克风和相册全部权限。
- 轻触反馈仅用于明确的选择、完成和确认操作；不在滚动、轮询、普通加载和每次字符输入时触发。
- 通过真实宿主能力触发触觉；普通网页或未支持设备自然省略，不模拟“已震动”的反馈。
- 列表转详情、Sheet 出入采用克制的运动。进入减少动态效果模式后去掉大位移、视差与连续弹动，使用即时状态变化或短淡入。
- 页面加载、生成、上传、失败和完成必须有可读文字。按钮禁用时说明原因，不能用无限转圈掩盖服务失败。

系统的减少动态效果设置需要影响自定义动效。[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)

## 8. iOS 完成门槛

- 视觉：相同页面的 iOS 与 Android 截图都能对应基准编号；平台差异记录到实施跟踪表。
