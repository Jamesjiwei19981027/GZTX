# Web / APP 五个主入口调整

2026-10-21，按已确认方案将主导航统一为：**工作｜人轴｜知识｜消息｜我的**。

## 页面归属

- **工作**：原待办、日历、项目进度、项目列表继续可用；新增显眼的“AI 汇报与助手”入口，进入个人项目 AI 对话、个人汇报、下属汇报收件箱、项目汇总和总领导摘要。
- **人轴**：继续展示人员责任链、材料、进展和节点操作；节点进入 AI 汇报或对话时自动进入工作归属的页面。
- **知识**：独立主入口，默认“我的知识”，可切换“项目知识”，继续按具体项目隔离。提供“询问知识助手”；该对话仍属于知识导航，返回知识空间。
- **消息**：群聊、私聊、工作联系人和通知入口保持可达。
- **我的**：账号、安全、外观、模型与服务配置等；原个人知识快捷入口仍可使用，会进入独立知识 Tab。

桌面 Web 侧栏使用相同五个一级入口。任务、看板、日历、AI 汇报、邮件收件箱、团队、通知渠道和回收站收在“工作工具与管理”，保留现有直接访问路径。浏览器窄屏与正式 APP 共用同一个移动导航。

## 兼容与项目隔离

- 原 `tab:'ai'`、`ai-*` 页面统一归工作导航，不新增第六个 Tab。
- 原 `me-knowledge` 页面统一归 `knowledge-root`。
- `?view=ai` 兼容映射为汇报与助手，`?view=me-knowledge` 映射为知识。
- 进入项目知识时保留 `knowledgeScope:'project'` 参数。
- AI 聊天与入口页的组件状态按项目、用户和路由模式重置，防止返回时显示错误页面。
- Web 的项目助手与 APP 使用相同 `/agents/chat` 接口，并带当前公司和项目范围。没有选择具体项目时不发送。

## APP 与 Web 同步约定

正式 Flutter APP 默认 `USE_WEB_SHELL=true`，加载与 Web 相同的 React 功能实现；移动路由和桌面侧栏同时调整。没有更改原生桥接协议或系统权限。本次对已安装的安卓 APP 直接读取最新共享界面进行验收。

仓库根 `AGENTS.md` 和 `.cursor/rules/web-app-sync.mdc` 已持久记录：每次产品修改必须同步完成 Web 与正式 APP，并检查相关导航、返回、权限和项目隔离。

## 验证

- 先修改五 Tab 顺序断言，确认旧实现失败，再实现新导航；路由及深链契约通过。
- 浏览器导航、个人/管理者汇报、知识、项目知识、首页与设置回归 25 项通过；独立移动页面覆盖 1 项通过。
- 独立复审发现 AI 路由模式切换不重置组件状态；补充回归先复现失败，再修复，相关导航与汇报 4 项复验通过。
- Flutter 壳测试 28 项通过；Web 类型检查、契约测试和生产构建通过，构建保留既有大分块提示。
- 真实桌面与安卓验收由 `frontend/scripts/test-five-tab-navigation-live.ts` 执行，**6 项检查通过**：桌面真实登录五主入口、桌面知识个人/项目切换、安卓 ADB 实点五 Tab、知识助手往返、工作 AI 入口与返回、旧 AI/知识深链。未模拟 API，也未写入业务测试资料。结果位于 `frontend/android-acceptance/test-results/five-tab-navigation/result.json`，同目录保留 desktop.png、android.png。
