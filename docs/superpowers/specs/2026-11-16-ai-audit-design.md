# AI 审计设计

依据：用户 2026-11-16 决定及 FEATAUD 实施要求。后端为权限权威，Web 与正式 APP 的 Web Shell 共享同一审计页面；保留原生 Flutter 审计入口。

## 范围与权限

所有请求先验证项目读权和有效企业身份。项目 `pm_user_id`（接口的 `final_owner_user_id` 为其别名）及 `created_by` 可审全项目及修改人员开关。公司管理员身份本身不增加审计范围。

本人范围为本人担任 primary 的人员节点及这些人员名下的事项，不穿过下属人员节点。领导开关有效时可以审自己人员节点下整棵子树，包含隔层下属。请求指定的 node 必须落在已授权子树内。第 1 层是根上的人，按人员祖先计数，第 1、2 层默认打开；第 3、4 层默认关闭。人员节点 `allow_audit_subordinates` 为可空布尔，null 恢复默认。暂不增加项目默认深度设置，以免引入用户未确认的配置项。

节点读取和开关写入统一走 TreeService。开关变更及审计发起写 AuditLog，与结果存档同事务。归档项目允许读历史，禁止发起及修改开关。

## 接口

- `GET /projects/{id}/audit-options`：后端计算允许的发起范围及管理开关列表。
- `PUT /projects/{id}/nodes/{node_id}/audit-permission`：`allow_audit_subordinates: boolean | null`，仅 PM/创建者。
- `POST /projects/{id}/audits`：`scope: self | node | project`，node 时必填 node_id；可选 custom_instruction，最多 500 字。非 node 请求不得夹带 node_id。
- `GET /projects/{id}/audits?offset=0&limit=30`：仅本人发起或针对本人的结果，分页。
- `GET /projects/{id}/audits/{audit_id}`：发起人可查看自己授权范围的快照；被审人只能看自己的条目，隐藏全局摘要、自定义要求、范围节点及其他人员信息，重新计算风险。
- 旧 `POST /projects/{id}/axis-audit` 保留一个版本：管理者 project，其他人 self，走新权限与存档，但强制 rule 模式，避免旧端意外触发模型费用。

## 审计与 AI

先对范围内全部人及事项做确定性检查：逾期、阻塞、7 天无进展、3 天内到期且进度低、完成却没有材料（标记待核验，不判造假）、人下无事项、人员终责指派缺失或祖先链断裂、工作量偏离范围平均值。工作量仅按事项数量估算，明确限制。材料关联性及汇报与事实矛盾交给 AI，证据不足必须说明无法判断。

普通审计调用 llm_from_company；自定义审查调用 resolve_llm(user=...)，来源 user 对外归一为 personal，保留 env 来源以反映实际行为。fake、禁用或不可用模型一律 rule。真实模型调用 chat_completion，提供范围内结构化人/事项、最近进度、汇报摘要、材料清单与抽取正文、规则指标；限制记录数和正文长度，总输入超过预算退回完整规则结果，避免漏人。数据与用户要求以 JSON 提供，系统提示禁止执行材料内的指令。

模型返回严格 JSON：overall_risk 与 nodes（node_id、risk_level、summary、findings[{type,description,matter_ids}]、suggested_actions）。仅保留范围内人员与该人员名下事项 id；剔除包含越界关联的发现。模型失败、JSON/字段不合规、结果漏人时整体降级规则版，存储可展示的固定原因，服务日志不输出密钥和原始材料。规则模式使用明确副标题：未配置 AI，以下为规则检查；调用失败用 AI 审计暂不可用，以下为规则检查。主模型调用最多 15 秒；收件人独立调用并发最多 4、总体最多 8 秒，以适应原生 APP 30 秒请求预算；超时使用已完成的独立结果或规则结果。

只按汇报作者判断范围不足：作者可能代他人操作、提交材料，或汇总下属汇报。汇总报告不接入；普通报告须有 AgentReportSource 并证明其全部来源属于当前人员的节点/事项，未知来源和无法证明的报告不送模型。规则材料存在性使用全量分组统计，不受正文截断预算影响。

## 存档与展示

新增 audit_runs 表，存项目、企业、发起人、范围、要求、模式、模型来源、风险、结果、时间。结果中的被审用户映射由服务端指派快照产生，不信任模型返回。历史列表与详情均执行相同裁剪，不能经计数、全局摘要或自定义要求泄漏其他人的结果。

多人员模型自由文本不能靠节点 id 过滤保证收件人隔离。因此存档另含 recipient_nodes：每个人以自己的材料、自己的规则指标独立调用模型，完全不提供他人数据、管理自定义要求和范围均值；该调用失败则保存该人的规则结果并如实标识。独立结果会增加模型调用数。工作量的全局比较只向发起人展示；收件人不返回全局比较。缺少可信独立快照的历史记录对收件人关闭展示。发起结束前刷新账号、会话、成员、项目和人轴，锁定并重新验证；撤权或责任链变动时不保存也不返回旧结果。

页面统一名为 AI 审计。提供范围、自定义要求、运行状态、历史和详情；项目设置提供人员审计开关（默认、打开、关闭）。纸与墨：纸色底、白卡、细线、墨蓝主按钮，500 标题，不用闪光图标。

## 验收

后端权限矩阵（本人、直属/隔层领导、第三层默认关闭/显式开关、PM、创建者、普通成员、外人）、跨项目、历史裁剪、fake 与坏 JSON 降级、越界 id、模型来源与输入边界；迁移升级降级。后端完整门禁通过后进入 Web，再进入 Flutter。保留所有门禁末尾原始输出，不提交。安卓模拟器可用时验收共享页面与原生页的返回；iOS、微信未执行明确记录。
