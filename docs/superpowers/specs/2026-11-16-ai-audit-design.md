# AI 审计设计

依据：用户 2026-11-16 决定及 FEATAUD 实施要求。后端为权限权威，Web 与正式 APP 的 Web Shell 共享同一审计页面；保留原生 Flutter 审计入口。

## 范围与权限

所有请求先验证项目读权和有效企业身份。项目 `pm_user_id`（接口的 `final_owner_user_id` 为其别名）及 `created_by` 可审全项目及修改人员开关。公司管理员身份本身不增加审计范围。

本人范围为本人担任 primary 的人员节点及这些人员名下的事项，不穿过下属人员节点。领导开关有效时可以审自己人员节点下整棵子树，包含隔层下属。请求指定的 node 必须落在已授权子树内。第 1 层是根上的人，按人员祖先计数，第 1、2 层默认打开；第 3、4 层默认关闭。人员节点 `allow_audit_subordinates` 为可空布尔，null 恢复默认。暂不增加项目默认深度设置，以免引入用户未确认的配置项。

节点读取和开关写入统一走 TreeService。开关变更及审计发起写 AuditLog，与结果存档同事务。归档项目允许读历史，禁止发起及修改开关。

## 接口

- `GET /projects/{id}/audit-options`：后端计算允许的发起范围及管理开关列表。
- `PUT /projects/{id}/nodes/{node_id}/audit-permission`：`allow_audit_subordinates: boolean | null`，仅 PM/创建者。
- `POST /projects/{id}/audits`：`scope: self | node | project`，node 时必填 node_id；可选 custom_instruction，最多 500 字。非 node 请求不得夹带 node_id。同步完成权限、材料快照与全部规则指标，存档后立即返回 `status=running`、`mode=rule` 及规则结果；请求不调用或等待模型。
- `GET /projects/{id}/audits?offset=0&limit=30`：仅本人发起或针对本人的结果，分页。列表、详情、发起响应统一返回 `status: running | done | failed`、`started_at`、`finished_at`；排队时 started_at 为空，后台认领时写入，终态写 finished_at。
- `GET /projects/{id}/audits/{audit_id}`：发起人可查看自己授权范围的快照；被审人只能看自己的条目，隐藏全局摘要、自定义要求、范围节点及其他人员信息，重新计算风险。
- 旧 `POST /projects/{id}/axis-audit` 保留一个版本：管理者 project，其他人 self，走新权限与存档，但强制 rule 模式，避免旧端意外触发模型费用。

## 审计与 AI

先对范围内全部人及事项做确定性检查：逾期、阻塞、7 天无进展、3 天内到期且进度低、完成却没有材料（标记待核验，不判造假）、人下无事项、人员终责指派缺失或祖先链断裂、工作量偏离范围平均值。工作量仅按事项数量估算，明确限制。材料关联性及汇报与事实矛盾交给 AI，证据不足必须说明无法判断。

普通审计调用 llm_from_company；自定义审查调用 resolve_llm(user=...)，来源 user 对外归一为 personal，保留 env 来源以反映实际行为。fake、禁用或不可用模型一律 rule。真实模型调用 chat_completion，提供范围内结构化人/事项、最近进度、汇报摘要、材料清单与抽取正文、规则指标；限制记录数和正文长度，总输入超过预算退回完整规则结果，避免漏人。数据与用户要求以 JSON 提供，系统提示禁止执行材料内的指令。

模型返回严格 JSON：overall_risk 与 nodes（node_id、risk_level、summary、findings[{type,description,matter_ids}]、suggested_actions）。仅保留范围内人员与该人员名下事项 id；剔除包含越界关联的发现。模型失败、JSON/字段不合规、结果漏人时整体降级规则版，存储可展示的固定中文原因，服务日志不输出密钥和原始材料。规则模式使用明确副标题：未配置 AI，以下为规则检查；模型失败或超时仍为 `status=done`、`mode=rule`，完整保留规则快照。

第二轮改用后台执行：主模型单次最多 180 秒，每位收件人独立调用最多 120 秒，并发最多 4，不再采用收件人总计 8 秒预算。`asyncio.wait_for` 限制整次调用，同时通过可选 timeout 参数将同样预算传至 Chat/Responses 底层 HTTP，避免底层默认 60 秒提前截止。原生 APP 原有 30 秒请求预算足以接收即时发起响应。维持 60000 字符、40 人上限，超过时中文提示并建议缩小范围，保留全部人员规则结果。

复用已有单进程 APScheduler：每 5 秒从 audit_runs 扫描排队中的 running，最多认领 4 条审计，用条件 UPDATE 原子写 started_at；每条审计拥有独立数据库会话。模型调用期间提交事务、释放数据库连接与人轴锁。普通 Web worker 不清理其他 worker 的任务；调度所有者在应用 lifespan 或独立 scheduler 进程启动时，将遗留 running 标为 failed，保存中文重启原因和规则结果。取消及未预期后台异常也终结为 failed，避免永久 running。使用现有 SCHEDULER_ENABLED 部署约定，无新进程类型或基础设施。

只按汇报作者判断范围不足：作者可能代他人操作、提交材料，或汇总下属汇报。汇总报告不接入；普通报告须有 AgentReportSource 并证明其全部来源属于当前人员的节点/事项，未知来源和无法证明的报告不送模型。规则材料存在性使用全量分组统计，不受正文截断预算影响。

## 存档与展示

audit_runs 表存项目、企业、发起人、范围、要求、模式、模型来源、风险、结果、时间。第二轮在 `ft8b9c0d1e2f` 后新增独立迁移 `fu9c0d1e2f3a`，增加 status、started_at、finished_at 和状态索引；历史记录回填 done，并用原 created_at 回填起止时间，不改写第一轮迁移。DEBUG SQLite 同步幂等补列。结果中的被审用户映射由服务端指派快照产生，不信任模型返回。历史列表与详情均执行相同裁剪，不能经计数、全局摘要或自定义要求泄漏其他人的结果。running 期间的内部 `_job` 保存原授权签名、会话撤销时间及有预算的材料快照，不包含模型密钥，不进入任何 API 投影；终态删除。

多人员模型自由文本不能靠节点 id 过滤保证收件人隔离。因此存档另含 recipient_nodes：每个人以自己的材料、自己的规则指标独立调用模型，完全不提供他人数据、管理自定义要求和范围均值；该调用失败则保存该人的规则结果并以中文回退原因如实标识。独立结果会增加模型调用数。工作量的全局比较只向发起人展示；收件人不返回全局比较。缺少可信独立快照的历史记录对收件人关闭展示。后台调用前和结果写回前刷新账号、会话、成员、项目和人轴，写回时锁定并重新验证；撤权或责任链/事项归属变动时丢弃 AI 结果、标为 failed，保留原规则快照，不写回旧 AI 结果。

页面统一名为 AI 审计。提供范围、自定义要求、运行状态、历史和详情；项目设置提供人员审计开关（默认、打开、关闭）。纸与墨：纸色底、白卡、细线、墨蓝主按钮，500 标题，不用闪光图标。

网页（桌面/手机/APP Web Shell）与原生 APP 发起后均显示“AI 正在审计，通常需要 1～3 分钟，可以离开此页，完成后在历史里查看”。停留页面时每 5 秒读取 running 详情，更新当前结果和历史；重新打开页面也恢复历史 running 的轮询。网页使用可清理的定时器，Flutter 使用 Timer；请求未结束不重叠启动下一轮。离页、切项目、切账号使旧响应失效，完成后不再请求该记录。历史显示“进行中 / 已完成 / 已退回规则检查”，客户端兼容缺少 status 的旧记录。完成通知为可选项，第二轮未增加站内通知。

## 验收

后端权限矩阵（本人、直属/隔层领导、第三层默认关闭/显式开关、PM、创建者、普通成员、外人）、跨项目、历史裁剪、fake 与坏 JSON 降级、越界 id、模型来源与输入边界；迁移升级降级。第二轮使用受控假模型验证立即 running、完成 done+ai、超时/异常/坏 JSON 的 done+rule 中文原因、收件人并发与超时、底层 HTTP 超时传递、权限/会话/归属变化丢弃、调度恢复及 running/done 被审人投影；网页行为与 Flutter widget 验证轮询、历史恢复、离页停止和旧响应隔离。保留所有完整门禁末尾原始输出，不提交。安卓模拟器可用时验收共享页面与原生页的返回；iOS、微信未执行明确记录。
