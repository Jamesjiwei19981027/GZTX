## 一、一句话定位

在**同一套产品**中，保留个人待办底盘；加建**按项目隔离的「项目管理树」**、**证据驱动的正式进度账本**、**一人一智能体本体 + 按项目分身**、**项目知识（LLM-wiki 思想）**，并通过站内 / 微信 / 邮件触达；支持**单公司 License 部署**与**类飞书线上开通**，组织架构**对接企业已有系统**，数据与算力路径由**公司策略引擎**按客户要求配置。

## 二、已锁定的核心原则（方案约束）

### 2.1 空间与真相

| 原则 | 说明 |
|------|------|
| 双空间 | 个人空间 + 团队/项目空间，同一 App |
| 分域权威 | 正式进度与项目知识以**项目树**为准；个人待办对项目事仅为**入口/投影** |
| 一项目一树 | 项目互不串数据；PM 管多项目 = 多棵独立树 |
| 同树叠职责与事务 | 节点既可表示责任范围，也可挂具体事 |
| 知识以项目为主 | 会/任务/材料默认服务项目知识；私人库仅习惯与草稿 |

### 2.2 进度与证据

| 原则 | 说明 |
|------|------|
| 拿材料说话 | 正式进度默认由材料驱动；纯口头不算 |
| 材料优先级 | 文件/链接 > 可核验产物 > 结构化表单 > 文字说明（语音先转写=文字） |
| 可配置例外 | PM 建树时可规定部分节点「说明写清楚即可推进」 |
| 自动落库 | 材料关过之后，**PM 智能体自动判并写正式进度**，再通知人 |
| 不可私自撤回 | 正式进度与已交材料当事人不可私自删改 |
| 更正 | 向人 PM 申请；人 PM 用自身智能体协调；可增量补充上下文后智能体再结论并倒逼讲清，**最终人 PM 确认** |
| 未采纳 | 不进 wiki，只留记录；可补交并要求复核；旧材料须**二次上传**；复核须**人 PM 确认** |
| 确认后四件事 | 更新进度（若适用）、沉淀知识库、通知提交人智能体、节点可追溯记录 |
| 自动写防呆 | 高频自动改进度**告警**；每次自动落库进**审计日志** |

### 2.3 智能体

| 原则 | 说明 |
|------|------|
| 本质 | LLM + harness（工具、记忆、权限、流程）= 智能体 |
| 个人 | 一个本体 + 按项目分身；最多 **5 个自创**（通用不占名额） |
| PM | 同一模型：本体 + 项目分身（在该项目行使 PM 职责） |
| 创作自由度 | 人设/工具/知识/模型/工作流几乎全可配，但受硬限制 |
| 硬限制 | 不破项目正式规矩；工具/出网在公司允许列表；不越权读数；高风险二次确认 |
| 分享 | 只读模板分享，对方复制为自有实例并占名额 |
| 场景 | 可按场景选用不同智能体（≤5 自创） |
| 模型 | 云 API 与私有模型均可配 |
| 交互 | 表述不清则倒逼写清楚；系统内与微信均可语音，统一转文字 |

### 2.4 组织、权限与商业

| 原则 | 说明 |
|------|------|
| 角色兼任 | 以「可兼任」为主；偶发跨项目总览与授权介入 |
| 开空项目 | 部门/团队负责人可开空项目，再指定/转让 PM |
| 改树 | 仅 PM 改整树；节点负责人仅可在**自己子树**下拆分/加子节点 |
| 负责人人数 | PM 建树时定义（单主责/多主责/主责+协助等） |
| 进项目 | 直接拉 + 邀请；**在职听组织**；跨部门默认可拉；公司可加严 |
| 退出 | 权限立刻收回；历史材料与进度保留可追溯 |
| 跨项目介入 | 与超管、该项目 PM 谈妥职权后授权；可走授权单或超管直授 |
| 超管 | **公司级**（无平台级超管）；每家公司各管各的 |
| 公司硬底线 | 留痕；不可私自删改进度/材料；退出留史；项目隔离；公司隔离 |
| 其余项目规矩 | PM 建树配置：成员角色、提醒通道与节奏、汇报模板；进度模型/材料门槛等按类型默认 + PM 可调 |
| 双交付 | 单公司 License 部署；线上个人可先用 + 开通服务解锁超管/企业能力 |
| License/开通 | 功能包、规模、期限**均可配** |

### 2.5 端与集成

| 原则 | 说明 |
|------|------|
| Web | 完整能力含建树、策略、PM 重操作 |
| 小程序 | 按权限/上下文分场景；交材料、对话、任务入口；复杂配置偏 Web |
| 微信 | 可聊、可更新；**不可交材料**；与小程序/企微双规划 |
| 通知首发通道 | 站内/Web + 微信 + 邮件（短信非本阶段必达，架构可预留） |
| 组织 | 通用对接层 + 企微/钉钉/飞书适配均规划 |
| 登录 | 账密、微信、企微/钉钉/飞书，公司超管开关 |
| ASR | 内置开源模块 + 云 + 企业自建；公司默认 + 个人在白名单内自选 |
| 文件 | 内置存储默认可用；可接客户 OSS/COS/MinIO 等 |
| 数据策略 | 公司级策略引擎 + 分项开关 + 预设档位（标准在线/企业可控/强隔离） |
| 会议 | 非主入口；任务以树上建分为主；预留腾讯会议智能纪要接入 |
| 升级 | 老个人数据全保留；不自动挂树；提供可选导入工具 |
| 语言 | 简体中文；国内时区为主 |
| 交付 | **全量方案、全量实现与验收**，不做 MVP 裁剪 |

## 三、产品形态与租户

### 3.1 两种交付模式

```
┌─────────────────────────────────────────────────────────────┐
│ 模式 A：单公司部署                                            │
│  License 生效 → 单租户公司空间 → 公司超管 → 组织/项目/策略     │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 模式 B：线上（类飞书）                                         │
│  个人账号可先用个人底盘 → 开通服务 → 解锁企业空间与超管         │
│  可创建/加入企业；多公司同部署时公司数据隔离                    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 租户与隔离

- **Company（公司租户）**：组织、策略、License/套餐、超管、存储与模型配置。  
- **User**：可属于 0..N 个公司；个人空间数据与公司项目数据分离存储命名空间。  
- **Project**：隶属唯一 Company；一棵 ProjectTree；独立成员、知识库、审计流。  
- 强制：**公司隔离、项目隔离**（硬底线）。

### 3.3 商业控制面

**Entitlement（权益）** 引擎统一服务 License 与线上开通：

- 功能开关（项目树、智能体、组织对接、强隔离档等）  
- 配额（人数、项目数、存储、LLM/ASR 调用）  
- 期限（到期只读/停用策略可配）  

运行时所有敏感 API 经 Entitlement + 公司策略双检。

## 四、领域模型（逻辑）

### 4.1 核心实体

| 实体 | 职责 |
|------|------|
| Company / OrgUnit / Membership | 公司、组织树、成员与负责人标记（以同步源为主） |
| User / PersonalWorkspace | 用户与个人空间（待办、私人知识、自创智能体） |
| Project | 项目容器；状态含进行中/归档规则（PM 可配） |
| ProjectTree / TreeNode | 一项目一树；节点含类型、负责人配置、计划时间、正式进度 |
| NodeType / BehaviorTemplate | 基础类型 + 自定义类型挂载行为模板 |
| Assignment | 树上责任与参与关系（主责/协助等由 PM 定义模型） |
| EvidencePackage（材料包） | 一次提交的文件/链接/产物/表单/说明；不可私自删除 |
| ProgressRecord | 正式进度变更账本（自动/确认/更正）；不可私自删改 |
| AdoptionRecord | 采纳/未采纳记录；未采纳不进 wiki |
| ProjectWikiEntry | 项目知识条目；默认仅 PM 与节点负责人可手写 |
| PersonalWikiEntry | 私人知识（习惯/草稿） |
| AgentDefinition | 通用/自创智能体定义（提示词、工具、模型、工作流） |
| AgentBinding | 用户默认/场景绑定；项目分身上下文 |
| ReportPolicy / NotifyPolicy | PM 建树配置的汇报与提醒规则 |
| DelegationGrant | 跨项目授权（范围、期限、授予人） |
| AuditLog | 全量关键操作与自动落进度审计 |
| IntegrationAccount | 企微/钉钉/飞书/通用同步与登录 |
| StorageBinding / ModelBinding / AsrBinding | 公司与个人可选的后端绑定 |

### 4.2 节点类型与进度模型

**基础类型（可命名微调）：**

1. **责任域（Scope）** — 职责范围；进度默认**汇总子节点**  
2. **任务/工作项（WorkItem）** — 状态机为主（未开始/进行中/受阻/待验收/已完成等），可附被证据支撑的完成度/检查项  
3. **里程碑/阶段（Milestone）** — 未达成/已达成（可选有风险）  

**自定义类型：** 必须选择 BehaviorTemplate ∈ {Scope, WorkItem, Milestone}，继承进度与默认材料门槛；PM 可加严。

**计划时间：** 节点可选 start_at / due_at / milestone_at；用于提醒与逾期；**主 UI 是树不是甘特**；是否强制由 PM 配置。

### 4.3 个人待办与项目投影

```
PersonalTodoItem
  - kind: personal | project_link
  - project_link → (project_id, node_id)   // 仅入口，非第二账本
```

更新正式进度**禁止**只改 personal 投影字段；必须走证据/说明 → 智能体链路 → ProgressRecord。

## 五、核心业务流程

### 5.1 开项目

1. 具备「部门/团队负责人」资格的用户创建 **空 Project**  
2. 指定或转让 **Project PM**  
3. PM 生成/编辑树：类型、负责人模型、计划时间、材料门槛例外、汇报策略、提醒策略  
4. 加人：组织在职校验 → 直接拉或邀请  

### 5.2 执行更新（系统内）

1. 用户与**当前项目分身**对话或表单提交  
2. 个人智能体：倒逼说清楚 → 模板预检材料/说明  
3. 若节点允许「仅说明」且验收通过：可直接写 ProgressRecord（仍审计）  
4. 若需材料：提交 EvidencePackage → PM 智能体分析  
   - 有用：自动写进度 + 沉淀 Wiki + 通知 + 审计  
   - 无用：Adoption=未采纳 + 通知个人智能体；wiki 不收录  

### 5.3 微信侧更新

- 可对话、可推进「说清楚」类更新（在规则允许时）  
- **禁止**上传正式材料；引导回 Web/小程序交材料  
- 语音 → ASR（公司默认或个人白名单选择）→ 文本 → 同 5.2 逻辑  

### 5.4 未采纳与复核

1. 补交须**二次上传**新材料包  
2. 可申请复核 → **人 PM 决策**  
3. 若智能体否、人 PM 认为可：人 PM 与提交人对齐 → **增量补充**给 PM 智能体 → 智能体出结论并倒逼 PM 讲清 → **人 PM 最终确认** → 执行「确认后四件事」  

### 5.5 更正正式进度

当事人不可直改 → 申请 → 人 PM + PM 智能体协调 → 确认 → 新 ProgressRecord（旧记录保留）+ 审计  

### 5.6 汇报

- 触发方式、模板、通道由 **ReportPolicy（PM 建树配置）** 决定：定时 / 有材料 / 混合 / 人确认后发送等均可  
- 个人分身按策略生成汇报 → 写入团队空间 → PM 分身可汇总、催办  

### 5.7 退出与归档

- 退出：即时 ACL 回收；历史 Evidence/Progress/Audit 保留  
- 归档策略：PM 可配（是否只读、是否可激活、谁可见）

## 六、智能体架构（Harness）

### 6.1 分层

```
┌─────────────── Agent Runtime ────────────────┐
│  Persona / Workflow / Tools / Memory          │
│  Policy Guard (公司策略 + 项目规矩 + ACL)      │
│  LLM Provider Adapter                         │
└──────────────────────────────────────────────┘
         │
    ┌────┴────┐
    │ 分身上下文 │ project_id + role(executor|pm|…)
    └──────────┘
```

### 6.2 内置工具（示例全集，受策略裁剪）

- 读：我的任务投影、节点详情、可见材料元数据、wiki 检索、审计摘要  
- 写（受规矩）：提交说明、创建材料包元数据、发起提交、申请复核/更正、生成汇报草稿  
- PM 工具：判材料、写进度、标未采纳、汇总子树、催办、受理更正（最终写仍要人确认的步骤卡人）  
- 通知工具：站内、微信、邮件（高风险二次确认）  

### 6.3 记忆

- 本体：跨项目的个人偏好（不含他项目机密）  
- 项目分身：该项目对话摘要、任务上下文、被授权知识切片  
- 项目 wiki：正式检索源（权限过滤）  
- 私人 wiki：仅本人与本智能体  

### 6.4 通用与自创

- 系统提供通用执行体、通用 PM 体（按角色启用）  
- 用户自创 ≤5；可导出为只读模板；导入占名额  
- 所有工具调用前：`authorize(user, project, action, resource)`

## 七、权限模型（RBAC + 资源 ACL + 授权）

### 7.1 角色层级

| 层级 | 角色 | 能力摘要 |
|------|------|----------|
| 公司 | SuperAdmin | 开通策略、组织对接、权益内配置、直授跨项目权、用户启停 |
| 公司 | OrgLeader | 开空项目等（以组织职务为准） |
| 项目 | PM | 整树、成员、策略、复核确认、更正协调 |
| 项目 | NodeOwner | 子树有限改结构、本域材料与手写 wiki |
| 项目 | Member | 执行、交材料、对话更新 |
| 跨项目 | Delegatee | 仅 DelegationGrant 范围 |
| 个人 | User | 个人待办与私人智能体 |

### 7.2 材料可见性

默认：提交人、节点负责人、项目 PM；同项目其他人是否可见附件细节由 PM 配置（默认偏「相关人」）。

### 7.3 小程序场景映射

登录后选择公司/项目上下文 → 按角色渲染导航：个人 / 执行 / 负责人 / PM 轻管理 / 授权总览；**鉴权以后端为准**。

## 八、集成架构

### 8.1 组织与登录

```
[企微/钉钉/飞书/通用连接器]
        ↓ 同步 OrgUnit + User + 在职状态
[Identity Service] ← 账密 / 微信 / 企业 SSO（公司开关）
        ↓
[ACL + Entitlement]
```

冲突策略：**在职状态以同步源为准**；项目成员关系在在职前提下由 PM 管理；公司可加严部门约束。

### 8.2 通知

统一 Notification Service：站内、微信（小程序订阅/企微应用消息）、邮件；项目 NotifyPolicy + 个人偏好；短信通道预留。

### 8.3 ASR

```
AsrRouter → BuiltinOpenSource | CloudVendor | CustomerHTTP
```

公司默认 + 用户白名单覆盖。

### 8.4 对象存储

```
StorageRouter → Local/MinIO内置 | S3/OSS/COS/客户桶
```

### 8.5 数据与能力策略引擎

预设档位映射到分项：`llm_egress`、`asr_egress`、`file_egress`、`allowed_model_ids`、`storage_mode` 等；Agent Runtime 与上传/识别链路强制检查。

### 8.6 会议（后续扩展点）

`MeetingImportAdapter` 预留腾讯会议智能纪要 → 生成建议任务 → 人确认后挂树（非首要入口）。

## 九、与现有 WorkTodo 的技术落位

### 9.1 现状真源

- `backend/` FastAPI：auth、tasks、categories、tags、reminders、notifications、attachments、wx  
- `frontend/` Vue3：仪表盘、任务、日历、设置  
- `miniprogram/`：任务/日历/设置等  

### 9.2 扩展策略（加层，不推翻个人底盘）

| 模块 | 动作 |
|------|------|
| 个人任务/提醒/邮件闭环 | **保留**；继续服务 personal 语义 |
| 新包 `projects` / `tree` / `evidence` / `progress` / `wiki` / `agents` / `org` / `entitlements` / `integrations` | 新建领域与 API |
| `users` / `auth` | 扩展多租户、SSO、开通态 |
| `notifications` | 扩展项目策略与统一发信 |
| `attachments` | 升级为材料包组件（可复用存储层） |
| 前端 | 新增：项目列表/树、材料提交、智能体对话、PM 工作台、公司管理；任务列表增加 project_link 入口 |
| 小程序 | 权限分场景改造 + 对话/材料/投影任务 |
| 调度 | 保留提醒扫描/邮件；新增汇报调度、组织同步、配额计量、审计告警作业 |

### 9.3 数据升级

1. Schema 迁移：加 company_id 等租户字段（部署模式默认单公司）  
2. 现有 tasks 保持 `origin=personal`  
3. 提供「导入为项目节点」工具（显式确认）

## 十、推荐技术架构（实现默认值）

> 下列为推荐默认，可在实施时替换，但须满足策略引擎与隔离要求。

| 层 | 推荐 |
|----|------|
| API | 继续 FastAPI，领域模块化；关键写操作事务 + 幂等键 |
| DB | PostgreSQL（多租户、JSONB 策略与审计）；生产避免仅 SQLite |
| 队列 | Redis + 异步 worker（判进度、汇报、同步、通知、ASR） |
| 搜索/知识 | 项目 wiki：权限过滤的全文 + 向量检索（可插拔 embedding） |
| 文件 | 默认 MinIO/本地；S3 API 兼容客户桶 |
| Agent | 自研 harness（工具注册、策略守卫、轨迹审计）；LLM 适配器多供应商 |
| ASR | 内置开源引擎进程/sidecar + HTTP 适配云/客户 |
| 前端 | Vue3 继续；树组件 + 对话台 + 公司管理台 |
| 小程序 | 原生或与现栈一致；上下文切换与权限路由 |
| 可观测 | 结构化日志、审计库、进度自动写告警、配额指标 |

**实时性：** 对话同步；判进度/沉淀/通知/同步**异步化**，UI 订阅任务状态；保证最终一致与可重试。

## 十一、API 域划分（逻辑分组）

```
/api/v1/auth/**          # 扩展 SSO、开通态
```

## 十二、安全与合规要点

1. 强制 ACL；禁止前端藏按钮式安全  
2. 材料与进度不可私自删改；删除类仅合规策略到期清理  
3. 审计日志独立存储、防篡改倾向（追加写）

5. 提示词注入与工具调用沙箱；外呼白名单  
6. 离职同步触发批量收权作业  
7. 策略档位「强隔离」下阻断外网 LLM/ASR/文件出域

## 十七、方案结论

本方案在现有 **WorkTodo 个人底盘**上，全量建设：

**项目管理树（职责+事务） + 证据化正式进度 + 项目知识库 + 通用/自创智能体（本体+项目分身） + 公司组织对接与双交付模式 + 可配置数据策略。**

正式协作真相在**项目树与进度/材料账本**；个人侧负责执行入口与私人智能体生产力；PM 智能体负责自动判定与统筹辅助，关键翻案与复核由**人 PM 确认**；系统用审计与策略引擎保证可追责、可隔离、可按客户要求部署。
