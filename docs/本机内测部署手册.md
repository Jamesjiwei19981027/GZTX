# 本机内测部署手册

> 适用对象：负责在自己电脑上把系统跑起来、邀请同事内测的负责人（不要求懂技术，照着做即可）。
> 重要说明：本手册里的 Docker 命令是按项目现有配置编写并做过“配置语法检查”，但编写时没有真正启动过这套内测环境。第一次照做时请逐步确认每一步的结果，遇到和手册不一致的地方先停下来，不要硬往下走。

## 一、先看结论

- 整套系统用 Docker 跑在你这台电脑上，同一个 Wi-Fi 下的同事用浏览器或手机访问 `http://你的电脑局域网IP:8088` 即可。
- 一共五件事：准备配置文件 → 生成授权密钥 → 启动 → 初始化（建公司和管理员）→ 登录后台填邮箱和 AI 密钥，然后发邀请链接。
- 三样东西丢了就无法补救，必须备份到安全的地方：**授权私钥文件、配置文件 `.env.beta`、安卓签名证书**。
- 电脑休眠、关机、换了 Wi-Fi，同事就访问不了；这是“本机内测”的天然限制，长期使用请迁到云服务器（见最后一节）。

名词先解释一遍：

- **Docker**：一个“集装箱”软件，把系统需要的数据库、后端、网页等打包成几个容器，一条命令全部启动。
- **容器**：Docker 里跑着的一个独立小程序。
- **局域网 IP**：你的电脑在家里或公司 Wi-Fi 里的地址，形如 `192.168.1.23`，同一个 Wi-Fi 的设备靠它找到你的电脑。
- **环境变量 / `.env.beta`**：系统启动时读取的“设置清单”，里面有密码和密钥，所以绝不能发给别人、不能上传。
- **PowerShell**：Windows 自带的命令窗口。开始菜单搜索 PowerShell 打开即可。本手册所有命令都在项目根目录（里面有 `docker-compose.prod.yml` 的那个文件夹）的 PowerShell 里运行。

## 二、准备工作（只做一次）

1. 确认电脑已安装并运行 Docker Desktop（右下角有鲸鱼图标，状态是 Running）。
2. 确认已安装 Python（命令 `python --version` 能显示版本即可），并安装两个小工具：

   ```powershell
   pip install pydantic-settings cryptography
   ```

3. 查你的局域网 IP：在 PowerShell 运行 `ipconfig`，找到正在用的网卡（无线是“WLAN”，有线是“以太网”），记下“IPv4 地址”，例如 `192.168.1.23`。下文用 `<本机局域网IP>` 代替它。
4. 建议在路由器里给这台电脑“绑定固定 IP”，否则重启路由器后 IP 可能变化（见“常见问题”）。

## 三、第一步：准备配置文件 `.env.beta`

1. 复制模板：

   ```powershell
   copy .env.beta.example .env.beta
   ```

2. 用记事本打开 `.env.beta`，把所有 `<尖括号>` 的占位符换成真实值。下面逐项说明值怎么来。

**怎么生成“强随机密钥”**：在 PowerShell 运行下面这条命令，每运行一次会得到一串不同的随机字符，复制它。每个需要密钥的地方都各运行一次，不要重复使用同一串。

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

| 配置项 | 怎么填 |
|---|---|
| `SECRET_KEY` | 生成一串随机密钥填入。它决定登录凭证能否被伪造，泄露等于系统被攻破。 |
| `APP_URL` | 填 `http://<本机局域网IP>:8088`，例如 `http://192.168.1.23:8088`。邀请链接和邮件里的网址都用它。 |
| `CORS_ORIGINS` | 填 `["http://<本机局域网IP>:8088"]`，保留方括号和双引号，IP 与上一项一致。 |
| `DB_PASSWORD` | 生成一串随机密钥填入，数据库口令。 |
| `DATABASE_URL` | 把里面的“与DB_PASSWORD完全相同”那一段换成上面的数据库口令，其余不动。两处口令必须完全一致，否则后端连不上数据库。 |
| `LICENSE_PUBLIC_KEY` | 先留着，第四步生成后再回来填。 |
| `INTEGRATION_SECRET_KEY` | 生成一串随机密钥填入。用来给后台里保存的邮箱授权码、AI 密钥加密；之后不要改，改了旧的就解不开。 |
| `REGISTRATION_MODE` | 保持 `invite_only`（只有拿到邀请链接才能注册）。 |
| `PHONE_VERIFICATION_REQUIRED` | 保持 `false`（内测没有短信服务，不要求手机验证）。 |
| `REGISTER_VERIFICATION_REQUIRED` | 保持 `true`（注册要邮箱验证码，所以第七步必须先配好发信邮箱）。 |
| `SMTP_*`、`IMAP_*` 等其余项 | 可以留空，发信邮箱稍后在网页后台配置。 |

填完后检查：文件里不应再有 `<` 或 `>`。

> 备份提醒：把 `.env.beta` 复制一份到 U 盘或密码管理器。它不在项目的版本管理里（已被忽略），丢了只能重新生成，而数据库口令一变，旧数据就进不去了。

## 四、第二步：生成授权密钥对

系统用“授权文件”控制公司能否使用、最多多少人、到什么时候到期。授权由一对密钥保证真伪：**私钥**用来签发授权（只能自己保管），**公钥**放进配置文件用来验证。

1. 选一个项目文件夹**之外**的位置放私钥，例如 `D:\gztx-keys`（脚本会拒绝把私钥放进项目目录，防止误提交）。
2. 运行（把路径换成你的）：

   ```powershell
   python backend/scripts/gen_license_keypair.py --private-key-file D:\gztx-keys\gztx-license.key
   ```

3. 屏幕会显示“私钥已保存到……”，以及最后一行的**公钥**（一长串字符）。把这串公钥复制，粘贴到 `.env.beta` 的 `LICENSE_PUBLIC_KEY=` 后面，保存。
4. 把私钥文件 `gztx-license.key` 备份到 U 盘或密码管理器。**私钥丢了，就无法再续期或调整人数。**不要发给任何人，不要放进项目文件夹。

## 五、第三步：启动系统

为了少打字，先在这个 PowerShell 窗口里设置四个“本窗口有效”的变量（每次新开 PowerShell 都要重新设置）：

```powershell
$env:COMPOSE_PROJECT_NAME = "gztx-beta"
$env:COMPOSE_FILE = "docker-compose.prod.yml;docker-compose.beta.yml"
$env:COMPOSE_ENV_FILES = ".env.beta"
```

含义：用名为 `gztx-beta` 的独立项目运行，叠加内测专用配置，读取 `.env.beta`。这样不会和你电脑上其他项目的容器、数据混在一起。

然后启动（第一次需要下载和构建，可能要十几分钟）：

```powershell
docker compose up -d --build
```

> 等价的完整写法是 `docker compose -p gztx-beta -f docker-compose.prod.yml -f docker-compose.beta.yml --env-file .env.beta up -d --build`，两种效果一样。

检查是否正常：

```powershell
docker compose ps
```

看到 `backend`、`db`、`nginx`、`frontend`、`scheduler` 的状态是 `running`（`migrate` 显示 `exited (0)` 是正常的，它只负责建表，做完就退出）。然后在本机浏览器打开 `http://localhost:8088`，能看到登录页就说明启动成功。

如果启动失败，先看日志：`docker compose logs backend --tail 50`。常见原因是 `.env.beta` 里还有占位符或密钥太弱，后端会故意拒绝启动。

## 六、第四步：执行初始化（建公司、建管理员、解锁授权）

刚启动时系统里什么都没有，需要运行一次初始化脚本：创建公司、创建第一个管理员、用私钥签发授权让公司解锁。脚本可以重复运行，已存在的东西会自动跳过。

准备 4 个信息：管理员用户名、管理员邮箱（要是你能收信的真实邮箱）、人数上限、授权到期日。管理员密码会在运行时让你输入（输入时屏幕不显示字符，输两遍；至少 10 位）。

```powershell
docker compose run --rm -v "D:\gztx-keys\gztx-license.key:/run/license.key:ro" backend python scripts/bootstrap_install.py --admin-username boss --admin-email boss@你的公司.com --private-key-file /run/license.key --max-users 30 --valid-to 2027-12-31 --company-name "我的公司"
```

说明：

- 前半段 `-v "D:\...:/run/license.key:ro"` 是把宿主机上的私钥文件“只读借给”临时容器，用完即销毁；私钥不会被复制进镜像。请把 `D:\gztx-keys\gztx-license.key` 换成你的实际路径，`boss`、邮箱、人数、到期日也换成你要的。
- 看到“初始化摘要”，并且最后一项是“公司状态：已解锁，可正常使用”，就成功了。摘要里不会出现密码或密钥。
- 想自动化时可以先设 `$env:BOOTSTRAP_ADMIN_PASSWORD`，但不推荐，交互输入更安全。
- 以后想续期或调整人数：在命令末尾加 `--force-license`，并换新的到期日和人数上限。

## 七、第五步：登录后台，填发信邮箱和 AI 密钥

1. 浏览器打开 `http://localhost:8088`，用刚才的管理员账号登录。
2. 进入「设置 → 企业管理」。
3. 填**发信邮箱**：填入邮箱服务器地址、端口、账号，以及“授权码”（不是邮箱登录密码，需要在邮箱网站的设置里开启 SMTP 并生成，QQ、163、企业邮箱都有这个入口）。填完点页面上的“发送测试邮件”，收到测试邮件才算成功。**这一步必须做**，因为同事注册时要收邮箱验证码。
4. 在同一区域的「AI 服务配置」里填 AI 模型接口地址、模型名称和密钥，点“测试连通性”，提示通过再保存。这些密钥保存在你自己电脑的数据库里，并用 `INTEGRATION_SECRET_KEY` 加密。
5. 密钥、授权码只填在这个页面里，不要发到聊天群里。

## 八、第六步：邀请同事

因为设置了 `invite_only`，同事不能自己随意注册，必须用你发的邀请链接。

1. 登录电脑端，进入或新建一个项目，在「团队」页面点“邀请”，填同事邮箱，系统会生成**邀请链接**，点复制。手机端在项目页有“复制专属邀请链接”。
2. 把链接发给同事（微信或邮件）。链接里的地址是 `.env.beta` 里 `APP_URL` 的值，所以同事必须和你在同一个 Wi-Fi 下才打得开。
3. 同事打开链接，填用户名、密码，收邮箱验证码完成注册，自动加入你的公司和项目。
4. 人数上限由第四步的 `--max-users` 决定，超过会提示名额已满。

## 九、手机和安卓 APP 怎么访问

**方式一：手机浏览器（最简单，推荐先用）。** 手机连接和电脑同一个 Wi-Fi，浏览器打开 `http://<本机局域网IP>:8088`。

**方式二：安卓 APP。** 需要有人在装了 Flutter 的电脑上打包，打包时把接口地址指到你的电脑：

```powershell
cd app
flutter build apk --release --dart-define=API_BASE_URL=http://<本机局域网IP>:8088/api/v1
```

- 打好的安装包在 `app/build/app/outputs/flutter-apk/app-release.apk`，发给同事安装即可（手机需允许“安装未知来源应用”）。
- 地址是写死在安装包里的：以后局域网 IP 变了，或者迁到云服务器，需要重新打包。
- 如果没配“正式签名证书”（见下一节），打出来的包只能做内测，不能上架应用商店。
- 项目的安卓配置已经允许访问 `http://` 开头的地址（内测需要）。迁到 HTTPS 后应关闭这个允许，见最后一节。

## 十、安卓正式签名证书

**为什么需要**：安卓要求每个 APP 安装包都有“签名”，用来证明“这个版本是同一个作者发的”。没有正式证书，每次打的包签名都不一样，同事无法在旧版上直接升级，也不能上架应用商店。

**为什么要备份**：证书只此一份，**证书文件和它的密码一旦丢失，这个 APP 将永远无法给已安装的用户做升级**，只能让大家卸载重装。务必备份到 U 盘和密码管理器各一份。

步骤（`keytool` 是 Java 自带的工具，装了 Android Studio 或 JDK 就有）：

1. 在项目文件夹**之外**生成证书（路径、别名按需修改，命令会提示你输入密码、姓名、单位等，密码请自己想一个强密码并记下来）：

   ```powershell
   keytool -genkey -v -keystore D:\gztx-keys\upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```

2. 新建文件 `app/android/key.properties`（项目里已经被忽略，不会被提交；已在 `app/android/.gitignore` 和 `app/.gitignore` 里确认），内容如下，把值换成你自己的：

   ```
   storePassword=<证书密码>
   keyPassword=<密钥密码，通常与证书密码相同>
   keyAlias=upload
   storeFile=D:/gztx-keys/upload-keystore.jks
   ```

   注意：路径用正斜杠 `/`。这个文件含密码，不要发给别人，也不要截图。
3. 打正式包时要求必须带签名，防止忘了配置：

   ```powershell
   $env:RELEASE_SIGNING_REQUIRED = "true"
   cd app
   flutter build apk --release --dart-define=API_BASE_URL=http://<本机局域网IP>:8088/api/v1
   ```

   没找到 `key.properties` 或内容不全时会直接报错，这是保护。
4. 备份清单：`upload-keystore.jks`、证书密码、密钥密码、别名 `upload`。

## 十一、备份与恢复

**为什么**：数据库和上传的文件都只在你的电脑里，硬盘坏了或误删就没了。建议每天备份一次，且上线前至少演练一次恢复。

项目里有现成的 `scripts/backup.sh`、`scripts/restore.sh`（Linux 服务器用的），它们写死了单个编排文件，**不能直接配合内测的叠加文件使用**（会找不到内测环境的数据库）。内测环境请用下面等价的命令，思路和脚本完全一样：数据库导出一份、上传的文件打包一份，两份要同一时间点配对保存。

先确认已经按“第三步”设置过那几个 `$env:` 变量，并在项目根目录。

**备份数据库**（文件会落在项目的 `backups` 文件夹）：

```powershell
docker compose exec -T db sh -c 'pg_dump -U worktodo worktodo | gzip > /backups/beta_db_$(date +%Y%m%d_%H%M%S).sql.gz'
```

**备份上传的文件**：

```powershell
docker compose exec -T backend sh -c 'tar -czf /tmp/objects.tgz -C /app/data objects uploads'
docker compose cp backend:/tmp/objects.tgz backups/beta_objects_日期.tgz
```

把 `日期` 换成当天，例如 `20261110`。然后把 `backups` 文件夹整份复制到另一块硬盘或 U 盘。

**恢复数据库**（会清空现有数据，不可撤销，先想清楚；`文件名` 换成真实文件名）：

```powershell
docker compose stop backend scheduler
docker compose exec -T db psql -U worktodo -d worktodo -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
docker compose exec -T db sh -c 'gunzip -c /backups/文件名.sql.gz | psql -U worktodo -d worktodo'
docker compose start backend scheduler
```

**恢复上传的文件**：

```powershell
docker compose cp backups/beta_objects_日期.tgz backend:/tmp/objects.tgz
docker compose exec -T backend sh -c 'tar -xzf /tmp/objects.tgz -C /app/data'
```

另有 `scripts/rollback-drill.ps1`（升级回滚演练）和 `scripts/soak-probe.ps1`（长时间探活），属于技术同事使用的工具，内测阶段不需要。

另外，授权私钥、`.env.beta`、安卓证书不在数据库里，要另外各备份一份。

## 十二、升级与回滚

**升级**（有新版本代码时）：

1. 先做一次“十一、备份”。
2. 更新项目代码（由技术同事给你新的文件夹，或在项目目录执行 `git pull`）。
3. 重新构建并启动：

   ```powershell
   docker compose up -d --build
   ```

   `migrate` 会自动把数据库升级到新版本的结构。
4. 用浏览器确认能登录、数据都在。

**回滚**（新版有问题想退回去）：

1. 把项目代码切回旧版本（让技术同事给出旧版本号，执行 `git checkout 旧版本号`）。
2. 如果新版已经改动了数据库结构，旧版本不一定认得，这时需要用升级前那份备份做“恢复数据库”。
3. 重新执行 `docker compose up -d --build`。

不要用 `docker compose down -v`：带 `-v` 会连数据库和上传的文件一起删除。普通停止用 `docker compose stop`，再启动用 `docker compose start`。

## 十三、常见问题

- **启动时提示 8088 端口被占用**：说明别的程序在用 8088。在 PowerShell 运行 `netstat -ano | findstr :8088` 看是谁。换端口的办法：编辑 `docker-compose.beta.yml` 里 `"8088:80"` 的前一个数字，同时把 `.env.beta` 的 `APP_URL`、`CORS_ORIGINS` 和安卓打包地址里的 8088 一起改掉。本机 80、5173、8010、8011、8013 等端口可能已被开发环境占用，内测不要用这些。
- **同事访问不了（但你本机能打开）**：多半是 Windows 防火墙。用管理员身份打开 PowerShell，运行下面这条放行 8088：

  ```powershell
  New-NetFirewallRule -DisplayName "gztx-beta 8088" -Direction Inbound -Protocol TCP -LocalPort 8088 -Action Allow
  ```

  同时确认电脑和同事的手机在同一个 Wi-Fi（不是访客网络，部分路由器的访客网络彼此隔离）。
- **电脑休眠后同事访问不了**：电脑睡着，系统就停了。用的时段内请在“设置 → 电源”里把“睡眠”设为“从不”，并插着电源。定时提醒和邮件由电脑上的后台程序发送，电脑睡眠期间同样不会发送。
- **局域网 IP 变了（重启路由器、换 Wi-Fi 后）**：同事会打不开，邀请链接和安卓安装包里的地址也会失效。处理办法：重新 `ipconfig` 查新 IP，修改 `.env.beta` 的 `APP_URL` 和 `CORS_ORIGINS`，运行 `docker compose up -d` 让改动生效，安卓包需要重新打包。预防办法：在路由器里给电脑绑定固定 IP。
- **后端起不来、日志里提到密钥太弱或占位符**：`.env.beta` 里还有 `<...>`、`change-me`、`example` 之类的字样，或密钥太短。重新生成并替换。
- **同事收不到验证码邮件**：回第七步，用“发送测试邮件”确认发信邮箱可用，并让同事看垃圾邮件箱。
- **初始化时提示“找不到私钥文件”**：检查 `-v` 后面冒号前的电脑路径是否正确，冒号后固定写 `/run/license.key`。
- **忘了管理员密码**：初始化脚本不会改已存在用户的密码。请联系技术同事在数据库里重置。（本手册编写时没有核实登录页是否带“找回密码”功能，不要依赖它。）

## 十四、以后迁到云服务器要改什么

内测稳定后，建议迁到一台云服务器（长期开机、有固定公网地址）。需要改的事项：

1. **域名**：购买域名，把域名解析到云服务器的公网 IP。
2. **备案**：服务器在中国大陆境内、用域名对外提供网站，必须先完成 ICP 备案（通常由云厂商代办，需要几周时间）；如果用境外服务器则不需要备案，但访问速度会受影响。
3. **HTTPS**：公网访问必须加密。步骤：
   - 在云服务器放开 80 和 443 端口（安全组里放行）。
   - 迁云时不再使用 `docker-compose.beta.yml`（它只开 8088），改用 `docker-compose.prod.yml` 本身，其中已映射 80 和 443。
   - 先只用 80 端口启动，按 `nginx/default.prod.conf` 开头的说明，用 certbot（免费证书工具）为你的域名申请证书。
   - 再把 `nginx/default.prod.conf` 里被注释的 443 段取消注释，把 `<你的域名>` 换成真实域名，然后重载 nginx：`docker compose exec nginx nginx -s reload`。
4. **环境变量**：把 `APP_URL` 改为 `https://你的域名`，`CORS_ORIGINS` 改为 `["https://你的域名"]`；其余密钥可沿用，也可重新生成（`INTEGRATION_SECRET_KEY` 和授权公钥如果换了，后台保存的第三方密钥和已有授权需要重新配置）。
5. **安卓 APP**：用新的 `API_BASE_URL=https://你的域名/api/v1` 重新打包；同时应关闭安卓工程里允许 `http://` 的开关（`app/android/app/src/main/AndroidManifest.xml` 里的 `usesCleartextTraffic`），这是技术同事的改动。
6. **数据迁移**：在旧电脑按“十一、备份”导出数据库和上传文件，在云服务器恢复（同样的命令）。
7. **自动备份**：云服务器是 Linux，可以直接用 `scripts/backup.sh`，并按脚本开头的说明设置每日定时执行。
8. **防火墙与端口**：云服务器上不要对公网开放数据库端口，只开放 80 和 443（以及远程管理用的 SSH）。
